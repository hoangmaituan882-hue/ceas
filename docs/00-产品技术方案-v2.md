## 1. 产品定义

**一句话**：本地优先的视觉灵感库，收集图片、视频、链接，整理成收藏集，用网格 / 画布 / 无限三种视图浏览。

**目标用户**：Windows 上的设计师、游戏美术、建筑与室内、电商视觉。他们的现状是「文件夹 + 截图 + 一个老旧的 Eagle 库」。

**不做什么**（防止范围蔓延）：
- 不做社交、不做信息流、不做推荐算法驱动的内容消费
- 不做团队协作（v1 明确排除，见 §11）
- 不做在线素材市场
- 不做移动端的画布编辑

**成功指标**：D7 留存 > 35%；收件箱 7 天内清零率 > 60%；「找到某张图」平均耗时 < 20 秒。

## 2. 领域模型

### 2.1 对象

| 对象 | 说明 | 关键规则 |
| --- | --- | --- |
| Library | 一个库 = 一个根目录 | 可有多个；切换时整棵 UI 状态重置 |
| Collection | 收藏集，归属维度 | 对应同名普通文件夹；支持子目录；跨集引用不改变原件主位置 |
| Board | 画板，空间维度 | 从属某个 Collection，不独立存在；一个集可有多张 |
| Item | 素材项 | 主键 UUIDv7 客户端生成；永不物理删除，只置 `deleted_seq` |
| Asset | 文件实体 | `库根/收藏集相对目录/原文件名.ext`；哈希只作内容指纹，同内容的不同文件位置分别保留；当前严格新格式不提供旧 blobs 兼容 |
| Source | 来源 | URL + 站点 + 抓取时间 + OG 图；一个 Item 可有多条来源（去重后） |
| Tag | 标签，属性维度 | 跨收藏集；标签可归入有颜色的标签组，组不是收藏集或文件夹 |
| SmartFilter | 智能入口 | 只做筛选，**不作为主归属** |

### 2.2 Item 核心字段

`id, hash, relative_path, kind(image/video/link/file), width, height, duration, size, aspect, ext, original_name, description, rating(0–5), source_url, source_site, dominant_color, palette[最多9], has_local_file, created_at, modified_at, deleted_seq, board_x, board_y, board_scale, board_z`

三个字段是能力分水岭：
- `hash` → 去重与来源合并
- `dominant_color / palette` → 颜色筛选 + 无限视图邻接
- `aspect` → 布局计算必须在缩略图生成时落库，不能等图片加载后读

### 2.3 不可违反的规则

1. 主归属唯一；跨集展示用引用，引用不复制 Asset。
2. 文件夹层级遵从真实目录，不截断导入层级；扫描设置 128 层安全上限，目录导航与同步实体 id 分离。
3. 画板必须有归属集。
4. 删除是软删除：`deleted_seq` + `v_*_visible` 读时视图；**禁止写时级联**。
5. tombstone 保留 30 天，且需 `min(活跃设备 last_seen_seq) > deleted_seq + grace`。
6. 所有主键客户端生成 UUIDv7。
7. 同步表禁开硬外键（跨设备到达顺序不确定）。
8. 智能集不参与归属计算。

## 3. 三视图内核

### 3.1 统一抽象

三个视图共用一套内核：`Item 图元 + 视口变换 + 命中测试 + 布局策略`。布局策略是可替换的三份实现，不许各写一套缩放和多选逻辑。

### 3.2 Grid

- 布局：justified，每行等高、两端对齐
- 密度档位：目标行高 S/M/L（如 160 / 220 / 300px）+ gutter 三档，落在 token 里
- 缩略图 LOD：64 / 512 / 2048，按缩放级别切换
- 交互：`Space` 浮层预览、方向键翻页、`Esc` 关闭、悬浮视频静音播放 3 秒（走代理文件）
- 性能：`@tanstack/react-virtual` + `content-visibility: auto`

### 3.3 Canvas

- DOM + `transform: translate3d/scale` + 绝对定位（5000 节点内够用）
- 坐标存 `board_x/y/scale/z`，属于 Board 而非 Item
- 吸附对齐、成组、套索多选、右下角小地图
- 缩放边界提示，避免用户「漂出画布」

### 3.4 Infinity

- 复用画布内核 + LOD 分级；**不提供编辑能力**
- 邻接顺序：同标签 → 同色系（Lab 距离）→ 同来源，而非随机
- 视口记忆：离开再回来停在原处
- 惯性滚动，滚轮速度即移动速度

### 3.5 跨视图一致性（必须做）

- 三视图共享**同一份筛选条件与选择集**：网格里选中 12 张，切到画布仍是这 12 张且已落位
- 网格 ↔ 详情的缩放是**同一元素的连续放大**，不是页面跳转
- 切换视图时保留滚动/视口位置

### 3.6 撤销

- M1：会话内 20 步内存栈（添加、删除、归档、标签、画板移动）
- M5：完整历史与跨会话撤销

## 4. 采集与导入

### 4.1 通道

| 通道 | 实现 | 备注 |
| --- | --- | --- |
| 剪贴板 | `AddClipboardFormatListener` + 全局快捷键 | 默认 `Ctrl+Shift+Space` |
| 文件拖入 | Tauri drag-drop 事件 | 必须用 Tauri 事件，HTML5 拖拽拿不到路径 |
| 文件夹拖入 | 当场二选一：导入 / 连接 | 选择结果记住，并说明差异 |
| 浏览器扩展 | MV3，Chrome + Edge 共用 | `127.0.0.1:随机端口 + 一次性 token`；检测不到桌面端才走云端 |
| 托盘拖放 | 落进收件箱 | 常驻场景 |
| 连接文件夹 | notify + debouncer | 只索引不搬运 |
| 移动端 | Android Web Share Target / iOS Share Extension | 只入队，不解码 |

**统一规则**：默认采集进入收件箱（库根目录）；Pixcall 或完整目录导入保留原目录结构，避免丢失已有整理结果。右下角轻提示 + 可撤销，不打断当前任务。

### 4.2 导入调度（底稿缺失，必须补）

状态机：`排队 → 探测 → 解码 → 缩略图 → 入库 → 完成/失败`

- 进度可见：「正在处理 342 / 1200」
- 可暂停 / 取消 / 失败重试
- 失败清单可导出（哪几个文件、什么原因）
- 全流程在 UI 线程外，IPC 只传 id 与状态，不传 buffer

### 4.2.1 实测数据（24 张真实素材 + 单张大图基准）

| 项 | 结果 |
| --- | --- |
| 24 张（333×270，13–30KB）全流程导入 | **299ms**（并发 3） |
| 单张 4000×3000 JPEG 处理 | 哈希 ≈0ms · 解码 19ms · 缩略图 19ms = **39ms** |
| 512 长边 WebP 缩略图体积 | ≈15KB（原图 335KB） |
| 外推 1000 张 | CPU 约 39s，三并发约 **13s**；缩略图共 ≈15MB |

结论：瓶颈不在哈希（WebCrypto 走原生），在解码与缩放。真实照片体积更大，按 2–3 倍估，
1000 张仍在 40s 量级 —— 关键是把解码放在 `createImageBitmap`（非主线程）而不是 `<img>`。

**缩略图策略（实测修正）**：源图长边 ≤ 512 时**不生成缩略图、也不单独存原图**，
直接把原图当缩略图。原因很实在：24 张 300 多像素的素材，缩略图总量 442KB，
原图 544KB —— 再编码一次不但没变小，还多了一次编码和一份存储。
实测 24 张里 21 张走「复用」路径、3 张（360×547 / 360×630 / 360×634）走「缩到 512 + 存原图」路径，
库内 originals 恰好 3 条、缩略图长边全部 = 512、Blob 均带 MIME。

### 4.3 去重

hash 命中时弹合并卡：「这张已有 3 处来源」，可选：
- 合并来源（保留一条 Item，追加 Source）
- 保留为独立项（确实要用同一张图表达不同意思）

### 4.4 文件三态

`有原图 / 未下载（占位）/ 文件缺失`

占位态（OneDrive、外接盘）用不同底纹 + 角标，缩略图不裂；文件缺失只影响打开，不影响浏览。

## 7. 技术架构

### 7.1 桌面壳

Tauri 2 + WebView2（Evergreen + bootstrapper 检测，fixed runtime 保底）/ Rust 薄层只碰六个 crate：notify、blake3、rusqlite、windows(WIC)、tracing、single-instance。

- 单实例：必须，双开会写坏 SQLite
- 开机自启：默认关
- 更新：tauri-plugin-updater + 签名密钥（私钥备份三处，丢了就发不了版）

### 7.2 数据层（R1 已决策）

- SQLite WAL + `synchronous=NORMAL`，连接池，禁止跨线程共享连接
- 迁移：`rusqlite_migration` 或自写版本表，必须可重入（用户可能跨六个版本升级）
- 类型共享：Rust 侧 schema 为唯一真相，生成 `packages/shared/schema.ts`；CI 里跑一个测试断言两侧字段一致
- 不引入 Drizzle

### 7.3 图像管线（已定：方案 R · 全 Rust）

**已决定采用方案 R**。理由：单一解码管线、无跨语言边界、内存与启动占优，且 WIC 本身就能覆盖 HEIC/RAW。体积不作为决策依据（见 [ADR 0007](adr/0007-drop-size-budget.md)）。

**方案 R 的组成**

- 缩放/编码：`image` + `fast_image_resize`（Lanczos3）
- HEIC / RAW / 冷门格式：WIC（系统 codec，用户装了 HEIF 扩展即可解 iPhone 原图、相机 RAW）
- 视频：ffmpeg 侧车（仅抽帧与 720p 代理），不做转码服务
- 动画 GIF：抽首帧做封面，播放走 mp4 代理

**方案 R 的唯一风险与对策**：AI 团队缺的是「用真实样本验证」的能力，不是写代码的能力。所以 M3 必须配一份 **24 个真实文件的格式矩阵**（iPhone HEIC、索尼/佳能 RAW、CMYK JPEG、16bit PNG、HEIC 序列、ProRes、竖屏手机视频、超长图、透明 WebP、损坏文件各一份），逐项验收缩略图与色彩是否正常。这份矩阵不通过，不许进 M4。

**两个方案共用的部分（不再变）**

- 缩略图多级：64 / 512 / 2048 / 原图按需
- 色彩管理统一走 sRGB，广色域源图在解码时转换，避免缩略图与原图偏色
- 缩放、着色、编码逻辑只存在一处

<details>
<summary>备选方案 N（Node 侧车，未采用，留档）</summary>

sharp/librsvg + WIC + ffmpeg 侧车；打包后约 90MB（Node 二进制 ~80MB，small-icu 可省 10MB）。优点是格式覆盖最稳、社区先例多；代价是跨语言边界与更高的构建/分发复杂度（体积已不作为否决理由）。若 M3 格式矩阵大面积不通过，可回退到此方案。

</details>

### 7.4 渲染

- 不上 WebGL；单屏可视节点破 8000 再考虑 PixiJS v8
- 合成层用 `transform` / `opacity`，避免布局抖动

### 7.7 前端组件层与图标（R8 / R9）

**Arc Library**（`kuratlielia/arc-library`，文档 uiarc.dev）

- MIT，React 19 + TS strict，**CSS Modules + CSS 变量**，动效基于 `motion`，通过 shadcn CLI 拷贝源码进仓库（不是运行时依赖）
- 免费：120 组件 + 22 区块；Pro：115 组件 + 114 区块（付费）
- 安装：`npx shadcn@latest add https://uiarc.dev/r/arc-foundation.json`，再按需加单项；`components.json` 里注册 `@uiarc` 命名空间
- 主题：`data-theme="dark"` + `data-accent`（neutral / violet / blue / green / amber / orange / coral / rose）

**Token 归属（关键决定）**

- 唯一真相是 Arc 的 `foundation.css` 变量。我们的间距阶、圆角三档、网格目标行高、gutter 全部定义为其扩展变量，**不新建第二套 token**
- Tailwind v4 只做布局：允许 `flex / grid / gap / size / inset / overflow`，**禁止**用它定义颜色、圆角、阴影、动效（必须走 `var(--arc-*)`）。加一条 stylelint 规则挡掉 `bg-* / text-* / rounded-* / shadow-*`
- 「明暗、背景、间距、圆角可调」直接映射到 Arc 变量 → 不用自建设置系统

**直接用 Arc 的**：button / action button / split button、dropdown menu、context menu、dialog、drawer、popover、tooltip、toast stack（撤销提示）、scroll area（网格边缘渐隐）、resizable panels（侧栏分栏）、segmented control（三视图切换）、tag input、color picker、progress / skeleton、empty state、tree view（收藏集树）、filter toolbar、card stack（过片骨架）、image compare、command palette（`Ctrl+K` 的壳）

**必须自建、不许外包的六块**：justified 虚拟化网格、画布内核、无限视图、过片的大图区与键位状态机、详情面板、按色筛选。理由：这六块就是产品本身；Arc Pro 里虽有 Inbox triage / Selection toolbar / Workspace sidebar，但买来改不动，且授权是长期成本。

**图标：akar-icons**

- MIT，434 个，React 组件，peer `react >=16`（React 19 可装），最后发布 2024-03：稳定，不再增长
- 设计基准 **2px 圆角描边**，props：`color / size / strokeWidth`。**不要为了「精致」改成 1.5px**，会破坏原始字形比例
- 命名反直觉，必须建映射：`Undo → ArrowCounterClockwise`、`Close → Cross`、`Trash → TrashCan / TrashBin`、`Settings → Gear`、`Infinity → Infinite`
- 缺口：没有 Canvas / Layers / Layout 类图标 → **三个视图图标自绘**（24px、2px 描边、圆角端点，与 akar 同源）
- 单一出口：`packages/ui/icon.tsx` 统一重导出，锁定尺寸档 16 / 20 / 24 与默认描边；业务代码禁止直接 import 图标包
- Arc 少数组件内部依赖 `lucide-react`（如可展开文本的箭头）：允许它作为传递依赖存在，但业务代码同样禁止 import lucide，避免两套图标混用

**工程约束**

- `packages/ui` 是 Arc 源码的唯一副本，desktop / web 都从这里引，不要每个 app 各 copy 一份
- 修改过的 Arc 文件顶部标 `// ARC-PATCH: 原因`，后续用 shadcn diff 升级时只合并未标记文件
- 打包方式：akar 是 CJS 单文件包，必须在构建期提取成静态 SVG（见 `docs/03` §6.1），否则 434 个图标会整包进产物；Arc 的 motion 与业务代码共享同一份运行时
- 补充依赖（Radix primitive、cmdk、culori、tinykeys、overlay 滚动条、字体、视觉回归）见 `docs/02-前端依赖清单.md`

### 7.8 同步（M3 起）

按底稿两条路线，铁律三条：可见性是读时谓词；tombstone 不立即删；同步表禁硬外键 + UUIDv7 主键。
自研路线必须配同步模拟器（双设备、随机延迟/离线/乱序，一万轮，断言收敛一致、无幽灵引用、无重复项）。

### 7.9 云端（M3 起）

首版改为用户自托管 Linux：桌面作为写入源，服务器接收并发布完整 revision，网页和手机读取服务端。资料仍按普通目录/原文件名保存；网络去重不改变文件树。PWA 按收藏集下载预览或原件，另设计可带走的 ZIP。具体部署、认证、断点、完整哈希与离线验收见 07。原 Postgres/R2/Workers 路线保留为未来规模化选项，本轮未实现服务端。

## 8. 工程铁律

1. IPC 不传大 buffer，只传 id 和状态
2. 禁止写时级联删除
3. sqlite-vec 只当缓存，接口收在 `VectorIndex` 三个方法后面
4. 不用客户端时钟做 LWW 定序
5. 主键客户端生成 UUIDv7
6. 路径全程 `\\?\` 前缀，库根目录限浅层
7. 图像解码只在一处（WIC），缩放只在一处
8. `packages/core` 与 `packages/views` 纯 TS，不依赖 DOM 与 Tauri
9. 每日 WAL checkpoint，备份必须含 schema 版本号
10. 快捷键占用失败必须显式提示
11. 业务代码禁止直接 import 图标包或 `lucide-react`，一律走 `packages/ui/icon`
12. Tailwind 不定义颜色 / 圆角 / 阴影 / 动效，只用布局类
13. Arc 源码只存在 `packages/ui` 一份，改动标 `ARC-PATCH`
14. 三视图图标与缺口的图标自绘，不引入第三个图标库
