# 前端依赖清单 · 补充选型

> 基线：React 19 + TS + Vite + Tauri 2 + Arc Library（组件/样式）+ akar-icons（图标）
> 原则：Arc 负责"长相"，这份清单只补它不提供的**行为**与**领域工具**；同一职责不允许两个库

---

## 1. 强烈建议补的六个

| 库 | 版本 | 补什么 | 为什么是它 |
| --- | --- | --- | --- |
| `radix-ui`（单包） | 1.8 | 无样式行为层：dialog / popover / dropdown / context-menu / tooltip / slider / menubar / toggle-group | Arc 内部已用 Radix 的部分 primitive，**同源零冲突**；Arc 没覆盖的（menubar、context menu 的嵌套子菜单、slider 键盘行为）直接拿 |
| `cmdk` | 1.1 | `Ctrl+K` 命令面板：分组、模糊过滤、键盘导航、选中态管理 | 事实标准；自己写键盘与滚动跟随至少要三天 |
| `culori` | 4.0 | 色彩科学：sRGB↔OKLCH/Lab、色距、色板提取、对比度计算 | 三个功能直接受益：按色筛选、Infinity 邻接的色距排序、CI 里的对比度校验 |
| `tinykeys` | 4.0 | 键盘序列（`g i`、`Shift+Delete`）、作用域 | 1KB，无依赖；过片界面的键位状态机靠它，比 hotkeys-js 轻且支持序列 |
| `@tanstack/react-virtual` | 3.14 | 网格与列表虚拟化 | 已在方案内，补充一点：justified 需要自己算行偏移，别指望它算布局 |
| `overlayscrollbars-react` | 0.5 | 跨平台 overlay 滚动条 | **Windows 上真实痛点**：WebView2 原生滚动条无法 overlay，宽 17px 且样式与 macOS 割裂，直接违背"界面消失" |

**滚动条的轻量替代**：如果不想引库，CSS `::-webkit-scrollbar` 在 WebView2 里可用，但做不到"仅 hover 显示 + 边缘渐隐"。我建议引库：这是少数改动很小就能明显提升质感的地方。

## 2. 已有但要划清边界的

| 库 | 边界 |
| --- | --- |
| `motion` | 只用于布局切换、FLIP、面板进出。列表项 hover 用 CSS transition，不要进 JS 动画循环 |

> **三个 "motion" 别搞混**
> 1. `motion`（motion.dev）—— 我们的动画库，前身叫 `framer-motion`，import 路径 `motion/react`。**用这个。**
> 2. `framer-motion` —— 同一个库的旧包名，禁止安装（装两套等于两份运行时）。
> 3. "Motion Agent"（transitions.dev）—— 动效扫描工具，与动画库**毫无关系**，见 §9。
>
| `@tanstack/react-virtual` | 只管"渲染哪几行"，justified 的行高与宽度分配是我们自己的布局策略 |
| `@dnd-kit/core` 6.3 | **只用于侧栏排序、标签排序、画板内少量拖动**。网格里的框选与万级拖拽必须自写 Pointer Events，dnd-kit 在这个数据量下会掉帧 |
| `zustand` | UI 态（当前视图、选择集、密度档位）。选择集用 `Set<string>` + 选择器订阅，别把整个 items 数组塞进 store |
| `zod` | 只用于边界校验（导入的 JSON、扩展传来的消息、IPC 载荷），不用于表单驱动的全量校验 |

## 3. 字体：对"高级感"贡献最大的一项非 UI 项

- 拉丁与数字：**Inter Variable** 或 **Geist**，本地自托管（`@fontsource-variable/inter`），不要 CDN——桌面端离线必须可用
- 中文：走系统（`PingFang SC` / `Microsoft YaHei`），不要打包中文字体（动辄 5MB 起）
- 字号回退顺序要写死，避免 Windows 上中英文混排基线跳动：`font-feature-settings: "tnum" 1` 只给数字用

## 4. 工程项：视觉回归（比任何 UI 库都更能保住风格）

`Playwright` + `toHaveScreenshot()`：

- 固定视口 `1440×900`、固定密度档位 M、固定素材集（20 张真实图）
- 三个页面截图基线：网格、详情浮层、过片
- 阈值 `maxDiffPixelRatio: 0.01`，只允许 1% 像素差
- 任何 UI 改动导致基线变化必须人工确认后更新

这条对"团队只有 AI"尤其关键：风格漂移是渐变式的，单次 diff 看不出来，但截图基线会立刻报警。

## 5. 明确不引入

| 不引 | 原因 |
| --- | --- |
| MUI / Ant Design / Chakra | 自带主题系统，与 Arc 的 CSS 变量体系冲突；体积与视觉语言都不合 |
| `@radix-ui/themes` | 那是 Radix 的**带样式**发行版，会跟 Arc 抢样式层。只用 `radix-ui` 的 primitive |
| shadcn 官方组件集 | Arc 本身就是 shadcn 变体，重复引入等于两套按钮 |
| `sonner` | Arc 已有 toast stack，两套 toast 必然打架。撤销提示走 Arc |
| 第二个图标库（Phosphor / Iconoir / Lucide 业务使用） | akar 缺口靠自绘补齐；混库会导致线宽不一致。**例外**：若最终核对发现 akar 覆盖不足 85%，整体换 Phosphor（weight 可调），而不是混用 |
| `tldraw` | 商用授权与免费版水印 |
| `react-spring` / `framer-motion` 旧包 | `motion` 已覆盖，别装两套动画引擎 |
| `tailwind-merge` / `cva` | 我们不用 Tailwind 类做样式，变体由 Arc 的 CSS Modules 承担 |

## 7. 体积参考（不作门槛）

> 2026-10-29 起**取消体积预算**（[ADR 0007](adr/0007-drop-size-budget.md)）。下表只记录当前实测/估算值，
> 用于回答「某个改动让产物涨了多少」，**不用来决定引不引一个依赖**。当前阶段优先把功能与手感做对。

| 项 | 记录值（gzip，非门槛） |
| --- | --- |
| `motion` | ~30KB |
| `radix-ui`（按需，实际用 6–8 个 primitive） | ~25KB |
| `cmdk` | ~8KB |
| `culori` | ~12KB |
| `overlayscrollbars` | ~10KB |
| 字体 Inter Variable（子集化后） | ~35KB |

仍保留的两条判断，理由与大小无关：

- **CJS 单文件包必须构建期提取**（`akar-icons` 就是这种，直接 import 会把 434 个图标全打进产物）。
  这不是"省体积"，而是避免产物里出现一整包用不到的死代码，拖慢启动与热更新。
- **搜索实现二选一**：`fuse.js` 适合模糊匹配；若只用前缀 + 分词，自写 200 行更可控。
  中文场景建议自写 bigram 匹配，与数据库索引共用同一套切分规则，**保证本地与云端检索命中一致**。

## 8. 附：AlignUI 评估（结论：不采用，只借架构）

已核对：`alignui.com` + `alignui/cli` 源码（v0.0.19，MIT，最后提交 2026-06）。

**它是**：Tailwind CSS **v4.1**（CSS-first `@theme`）的拷贝式设计系统，React + Radix（`asChild`），OKLCH 色彩，自带亮暗模式与主色切换。CLI 命令 `npx @alignui/cli tailwind` 生成整套 token。

### 8.1 基础样式实测数值

| 项 | 实际值 | 与我们的规范 |
| --- | --- | --- |
| 圆角 | 只有 `10px` 与 `20px` 两档 | 冲突：我们要 4（缩略图）/ 6（列表）/ 10（面板），组件全部按 10px 设计 |
| 字号 | 11px → 56px 共 6 档标题 + 4 档标签 + 5 档正文 + 4 档小标题（+0.06em 字距） | 冲突：我们只允许 11/12/13/15/17；它的 subheading 是「全大写小标题」风格 |
| 阴影 | 4 套共 30+ 个：`regular-*`、`complex-1..12`、`fancy-buttons-*`、`custom-input-*` | 冲突：我们只允许两层阴影，且内容卡片禁止阴影 |
| 色彩 | 0/25/50…950 全阶 + `strong/sub/soft/disabled` 语义 + `alpha-24/16/10` | **优于我们**：三层命名与 alpha 变体可直接借用 |
| 主色 | Blue / Purple / Orange / Green（500 与 400） | 可借鉴：一套主题切换的落地方式 |
| 间距 | 无独立 spacing token，走 Tailwind 4px 基准 | 兼容：与我们的 4–48 阶天然吻合 |
| 图标 | Remix Icon（`@remixicon/react`） | 冲突：与 akar-icons 决策重复 |

### 8.2 判断

- **优点**：token 体系比 Arc 完善，自带主色/明暗/圆角开关，正好对上我们「外观可调」的产品特性；组件偏表单与后台（180+），工程完整度高。
- **问题**：视觉语言是「企业 SaaS 仪表盘」——10px 圆角、30+ 阴影、大字号阶，与 Atlas 式的克制是两套美学；组件全用 Tailwind utility，与 Arc 的 CSS Modules 不能共存；CLI 会**覆盖**现有 CSS 与 tailwind 配置；免费仅 40+ 基础组件，180+ 主要在 Pro。
- **结论**：不做补充，也不混用。要换只能整体替换（重写视觉规范 + 接受 Remix Icon + 放弃 CSS Modules），代价高于收益。

### 8.3 只借四件事（零依赖）

1. **色阶命名**：`0/25/50/…/950` + `strong/sub/soft/disabled` + `alpha-10/16/24`，比我们现在的三级文字色更成体系，改造 `--text-*` 为这套命名。
2. **圆角开关机制**：它用 `S/M/L` 切换圆角主题——我们的「圆角可调」直接抄这个做法（S=4/6/10 收紧，M=6/8/12，L=8/10/14）。
3. **OKLCH 作为默认色彩格式**：与 `culori` 一致，色距计算更准，暗色映射不用手调。
4. **`@theme` CSS-first 生成 token**：Tailwind 只做布局，但 token 由 `@theme` 生成，布局类与 CSS 变量共用一套来源，不会漂移。

## 9. 附：Transitions.dev 评估（结论：部分采用，工具优先）

**它是三样东西**：43+ 个手调 UI 过渡配方 + Studio 构建器（桌面端）+ Motion Agent（终端与 GitHub Action，扫描动效并给 0–100 分）。

### 9.1 值得用的部分

| 部分 | 判断 |
| --- | --- |
| **Motion Agent**（`npx transitions-agent`） | **真价值**。确定性扫描、不上传代码、无 AI 参与；免费版无限扫描 + PR 门禁 + 每月 10 次托管修复。对「只有 AI」的团队，等于一个自动化的动效审查员，正好补上设计规范 §10 里「非空间动效只能用三档时长」这条**没有工具执行**的规则 |
| **配方库里的十来个** | 与我们缺的细节完全对应：panel reveal、modal open/close、menu dropdown（origin-aware）、tooltip（延迟进 / 跟随 / 瞬间出）、toast、accordion（grid-rows 高度 + chevron morph）、icon swap、skeleton→content 交叉淡入、checkbox 勾线、success check、spinner→check、tabs 滑块、number pop-in。多数只动 transform / opacity，符合规则 |
| **自己的 skill** | 首次运行会装进 `~/.claude/skills`，之后「检查这个应用的动效」就能让 agent 自己扫、给方案、执行、复验 |

### 9.2 不用的部分

3D tilt、彩色光晕按钮、gooey 展开菜单、点赞粒子、confetti、烟雾删除、渐变文字——这些正好命中设计规范 §9 的反例清单。它的 Pro 库大半是炫技型，与 Atlas 的克制相反，**不要整套引入**。

### 9.3 三个必须先确认的冲突

1. **时长刻度**：Agent 的 polish 模式会把动效归一到**它自己的刻度**（例：300ms 的模态关闭→150ms）。我们要求 140/200/280，若刻度不可配置，它会持续把我们的值改错。**用之前必须先跑一次 dry scan 看它的输出，确认可配或不影响我们的三档。**
2. **blur 依赖**：配方大量使用模糊交叉淡入。我们只允许在状态切换里用（保存→已保存），列表与网格内禁用。
3. **代码形式未知**：Studio 需桌面端打开，无法在移动环境确认配方产出的是 CSS keyframes 还是 React + Motion 组件。若是纯 CSS keyframes，与我们的 `motion` 组件混用会出现两套动效心智；若是 React 配方则完美契合。**打开 Studio 看一眼 panel-reveal 的源码再决定。**

### 9.4 采用节奏

- M0：只用它的配方做**参考**（看别人怎么处理 tooltip 的进出不对称），不接工具
- M1 骨架跑起来后：`npx transitions-agent` 跑一次基线，把 finding 当作「我们规范执行情况」的第三方体检
- M2 起：若刻度可配且代码形式兼容，再决定是否接 GitHub Action 做 PR 门禁（免费版够用，Business $59/mo 才有 revamp 与门禁）

## 10. 版本锁定（实测结论）

| 依赖 | 锁定 | 原因 |
| --- | --- | --- |
| `vite` | **7.x**（不用 8） | vite 8 的 rolldown 在 Windows 上偶发 `0xC0000005` 原生崩溃：实测 5 次构建挂 2 次；退回 7 后连续 3 次通过 |
| `typescript` | **5.9**（不用 7） | TS 7 移除了 `baseUrl`，且 `tsc` 行为与生态不一致 |
| `@vitejs/plugin-react` | 5.x（配 vite 7） | 与 vite 8 的 6.x 分支不通用 |
| `playwright` | 最新 | 只用于走查与截图基线，不进产物 |
