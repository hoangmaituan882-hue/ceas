# Windows 客户端开发计划

> 目标：把浏览器版（Vite + React + IndexedDB）变成能装、能拖文件、能管几十 GB 素材的桌面应用。
> 壳用 Tauri v2（Rust + WebView2）：内存占用低、启动快，文件系统能力足够，不必为几件插件引入整个 Node 运行时。
>
> **当前状态**：资料库格式 schema 5 与本地管理（创建/打开/切换/改名/迁移/文件核对/回收/收藏集）已落地，
> 见下文「资料库管理」、[08](08-资料库管理完整方案.md) §21 与 ADR 0004–0006。本文件其余章节按时间保留，
> 其中 Phase 1/2 的原件布局已被 [ADR 0002](adr/0002-open-folder-library.md) 取代。

## 现状（M0 已完成）

- 前端：三视图（网格/画布/无限）、双排布、视频播放、导入流水线、坐标持久化、右键标签
- 数据：桌面端以 SQLite 保存素材、标签、画布与视口；原件使用普通文件夹/原文件名，辅助信息在 `.ceas`，不提供旧 Ceas 自动升级。IndexedDB 只作可重建缩略图缓存；浏览器开发模式使用 IndexedDB v4，不等于未来读取服务端的网页应用。
- 桌面壳：Tauri 已接资料库、原件、Pixcall 和主库存取接口；修改 Rust 后必须重新编译并重启，前端热更新不能更新原生接口。

## 资料库管理（2026-10-29 已接原生）

首启展示 idle 吉祥物、新建/打开/Pixcall 导入和稍后设置。无库时可停留管理页或看引导；工作区需要有效库。顶部库名旁、设置提供统一管理入口，引导逐步可跳过并可后续重开。

- 自定义名称和本地位置；可原地管理已有普通目录。创建前只预览，打开已有库不创建缺失文件。
- 最近库、多个库切换、单独改显示名、当前库可选根目录改名、复制并校验迁移、外部移动后重新定位。导入时可等待完成或停止收尾后切换。
- 非 C 盘 `CEAS_CONFIG_DIR/libraries.json` 登记最近库/当前库/引导；未指定时使用可执行文件旁 `ceas-config`。WebView profile 和临时目录也在非 C 盘，不读取旧 settings 自动建库。
- 库内 `.ceas/library.json` 和 `library.db` 核对 UUIDv7/格式，SQLite WAL + FULL；独立会话锁和代次阻止其他进程与迟到请求写入。故障保留原件，迁移保留原副本。
- `library_manage` 统一管理命令；文件/存储请求绑定根位置和会话。设计、限制和验证见 08 §21.1、09、ADR 0004。
- 验证：`pnpm test:storage -Browser`、`pnpm check:library-native`。后者需要隔离原生宿主，读取本轮 `.cache/tmp/library-management-latest.json`；不会自动接管用户正在运行的窗口。

## 搜索、排序、筛选（已实现）

- 顶部三个工具入口可打开对应面板；`Ctrl+K` 聚焦搜索，`Esc` 关闭并回焦，点外部关闭。设置、详情与过片打开时不在后台打开搜索。
- 搜索使用完整文件名、目录、标签、描述、来源 URL/站点和代表色色名；中文切 bigram，多关键词 AND 匹配。输入中的空格和快捷键不会穿透到素材预览。
- 排序支持导入时间、自然文件名、文件大小、宽高比的双向排序；默认最早导入优先，排序偏好本地保存。未知元数据始终排后，旧库无需迁移。
- 筛选支持素材类型、宽高比、标签、来源站点、代表色、亮度、饱和度、评分、相似颜色、视频时长和日期。来源站点仅在有此元数据时显示；未知时间、时长或颜色不参与相应筛选，不填造数据。
- 日期按本地自然日筛选，结束日包含当天；色族使用九色样本做 HSL 粗分，另有 Lab / ΔE76 相似色筛选，算法边界见 07。
- 三视图共用 `packages/core/item-query.ts` 的纯 TS 查询结果；详情按当前结果顺序翻页。查询条件跨视图保留，搜索与筛选刷新后清空；清除条件不重置排序偏好。
- 隐藏项的选择仍保留，批量操作仅作用于当前结果中的选择；批量条退出动画期间立即禁止操作。筛选、恢复画布素材时合并坐标，避免丢失隐藏项的位置。画布仍保留现有前 48 项限制，本轮未扩展画布规模。
- 工具图标沿用密度 token；清除浏览器按钮默认内边距，确保三档密度下图标与深色选中背景共用中心。没有新增第三方依赖或修改设计 token。

验证入口：`pnpm test:query`（查询规则与一万项性能），`pnpm check:query-design`（新增工具的设计断言），`pnpm check:query-ui`（独立浏览器上下文的组合条件、键盘、三视图、坐标与三档密度走查）。界面走查默认连接 `http://127.0.0.1:5174`，可用 `APP_URL` 指向其它开发端口；测试不接管用户桌面窗口或写入用户资料库。

## Phase 1 · 本地文件（最优先）

> Phase 1/2 与其下旧 Pixcall 实测保留开发历史；其中旧布局、直接打开源库、只收图片/视频及前端解码建议均已由本文件末尾的普通目录阶段、07、ADR 0002 和 00 §7.3 覆盖，不能作为当前实现或下一阶段约束。

**为什么先做这个**：现在"导入"是从开发态 HTTP 服务拿字节。真实用户不会把素材放在 Vite 中间件后面，
必须能从磁盘读——这是"能不能真的用"的分水岭。

- [ ] `import_folder(path)` command：递归扫描，返回 `{ path, name, size, mtime }`
- [ ] `read_file(path)` → 前端拿 `ArrayBuffer` 做哈希/解码/缩略图（复用现有 `importer.ts`）
- [ ] 拖放：Tauri 的 `dragDropEnabled` 已开，接 `onDragDropEvent` 拿到路径列表
- [ ] 记住上次导入的目录

**关键约束**：解码与缩略图仍在前端做（`createImageBitmap` 非主线程），不要在 Rust 里解码——
否则要引 image crate，二进制变大且收益不明显。

## Phase 2 · 原图落盘（历史记录，方案已被 ADR 0002 取代）

> **不要照本节实现。** 这里写的是「内容寻址 blobs」方案：`<library>/blobs/<hash前2位>/<hash>.<ext>`。
> 2026-10-29 的 [ADR 0002](adr/0002-open-folder-library.md) 已推翻它 —— 新原件改为
> **普通收藏集目录 + 原文件名**，哈希只作内容指纹，同内容出现在两个目录算两条素材。
> 当前布局见 [07](07-开放资料库与同步离线方案.md) §1、[08](08-资料库管理完整方案.md) §3，
> 实现见 `src-tauri/src/library_files.rs` 与 `library_scan.rs`。
> 本节保留的价值只有两点：为什么当时先做落盘，以及踩过的坑（HTTP Range、原子写、大小写冲突）。

旧版原图存在 IndexedDB 里。几千张原图（几十 GB）撑不住。

- [x] 内容寻址：`<library>/blobs/<hash前2位>/<hash>.<ext>`
- [x] `write_blob` / `blob_exists` / `delete_blob` / `init_library`（`src-tauri/src/blob.rs`）
      写入用「同目录临时文件 + rename」，避免半个文件；已存在则跳过（幂等）
- [x] `save_blob` / `load_blob` / `blob_count` 三个 IPC 命令；导入时前端把原图写盘
- [x] 设置页显示「已落盘 N 个原图文件」
- [x] **读路径已切到磁盘**：详情页先 `load_blob`，取不到才退 IndexedDB
- [x] 新导入**不再双写**：落盘成功就不进 IndexedDB（落盘失败才回退）
- [x] 迁移：设置 ▸ 通用 ▸「迁移历史原件到磁盘」，逐条复制，当前版本保留原件备份，不自动清理

实测：导入 1 张新图后 IndexedDB `originals` 从 9 不变、磁盘 30→31；
双击打开详情，图片 768×3452 正常显示 —— 而 IndexedDB 里没有它的原件，只能来自磁盘。
迁移后 `originals` 9 → 0，磁盘仍是 32（内容寻址让历史原件无需重写，只删索引）。

实测（CDP 接管原生窗口）：导入 24 张 → 磁盘 `blobs/<xx>/<hash>.jpeg` 24 个文件，
抽样 8 个做 sha256 比对全部与文件名一致；设置页显示「24 个原图文件」。

## Pixcall 支持（已实现）

Pixcall 的库 = **普通目录树 + SQLite 元数据**（`<lib>/.pixcall/database/main.db`）。
所以「支持 Pixcall」不是导入一个私有格式，而是读懂它的元数据：

| 表 | 用途 |
| --- | --- |
| `entries` | `kind` 0=文件夹 1=文件；`parent_id` 构成树；`tags` 是 `|` 分隔的标签 **id** |
| `tags` | 标签 id → 名字 |
| `folders` | 文件夹的展示属性 |

实现（`src-tauri/src/pixcall.rs`）：

- 只读打开数据库（`SQLITE_OPEN_READ_ONLY`），**绝不写对方的库**
- 路径没存，必须沿 `parent_id` 往上回溯名字拼出来；根文件夹（id=1）的名字要剥掉
- `tags` 列存的是 id，要和 `tags` 表 join 才能变成可读标签
- 沿链回溯加了 64 层上限，防止脏数据造成死循环

导入：设置 ▸ 通用 ▸ Pixcall 资料库 → 选目录 → 扫描（显示「可导入 N 个 · 共 M 条 · K 个在磁盘上 · J 个标签」）→ 导入。

**只收图片与视频**：Pixcall 库里混着字体（`.ttf`）、PDF、音频、`.eaglepack` 包，`createImageBitmap` 解不了。
实测该库 5806 条里 5667 个在磁盘上，其中图片/视频才是可导入的。

实测（CDP 驱动原生窗口）：取 6 个带标签的图片条目 → 导入 6/6 → 标签原样进入我们的标签库
（`日式动漫风格 / 女性角色 / 贝雷帽 / 画师bilibili Ar2a` 等），确认没动 Pixcall 原库。

## Phase 3 · SQLite（历史记录，当前管理格式见上文）

主读写已接管，不再把桌面端写入失败静默退回浏览器存储。

- [x] `items / item_tags / store_state`，SQLite WAL + NORMAL；每次写入等待事务提交。当前 `user_version=4`，新增普通相对路径、描述、URL、评分、九色索引、修改时间，取消唯一哈希约束；旧表原位升级，较新版本数据库拒绝降级打开。
- [x] 删除写库内递增 `deleted_seq`，读取走 `v_items_visible / v_item_tags_visible`；回收站走删除谓词。素材、原件、标签和画布坐标都不写时级联删除；普通 upsert 和重复迁移不能复活墓碑。
- [x] 删除后可撤销；侧栏回收站支持重启后查看、选择与恢复，恢复保留原 id、标签和原件。没有永久删除入口或自动 GC。
- [x] 迁移先核对原件：已有文件跳过；缺少文件时从旧原件或未缩放的小图复制，哈希不符则停止。之后在同一事务提交元数据、标签、旧界面状态和完成标记；失败可重试，旧 IndexedDB 与 localStorage 保留。
- [x] 自动迁移只接受与当前影子库素材哈希有交集的旧数据；新建空库不自动吸入无归属缓存。其它情况通过设置中的「迁移旧版资料到当前库」明确执行；旧数据只认领一个目标库。
- [x] 素材和标签的读写固定资料库根目录，后端拒绝过期目标；切库前等待未完成标签和界面状态写入。切库重建界面状态，画布、视口、条件、选择和标签不串库。
- [x] 新导入使用 UUIDv7；迁移保留历史 id，避免破坏标签和画布引用。删除定序使用 SQLite 序号，不使用 UUID 时间戳或客户端时钟。
- [x] 缩略图迁入独立 `ceas-thumbnails` 缓存；清空缓存仍可按 SQLite 元数据从盘上原件重建。缺图或坏图用占位保留条目，不让整库读取失败。

本轮范围不包含：收藏集/画板的完整关系模型（画布状态暂存库内 JSON）、永久删除与同步 GC、分页读取、Rust 图像解码管线。现有媒体字节传输仍沿用既有接口，本轮新增存储接口只传元数据、id 和状态。

验证：`pnpm test:storage` 运行原生迁移与事务测试；开发服务启动后，`scripts/test-storage.ps1 -Browser` 构建同源存储验证程序并运行隔离双库联调；`pnpm check:storage-native` 连接专用 `9223` 测试窗口验证真实 Tauri/WebView2 链路。默认开发端口 `5174`，测试库、配置、WebView2 用户目录和截图全部在项目 `.cache` 下；不会接管用户正在使用的窗口。

## 风险与决定

| 风险 | 处理 |
| --- | --- |
| WebView2 缺失（旧 Win10） | NSIS 安装包内置 bootstrapper；已在 `tauri.conf.json` 用默认行为 |
| 首次 `cargo build` 很慢（本次约 7 分钟） | 只影响开发机；CI 缓存 target 目录 |
| 大量文件扫描卡 UI | Pixcall / 磁盘扫描和原件复制使用原生后台任务；当前扫描仍一次返回清单，批次事件和增量扫描待做 |
| 内存：大图解码 | 仍然 512 缩略图优先；详情页才读原图，且用 `createImageBitmap` |

## 不做

- 不做 Electron（内存占用高、启动慢，还要同时维护一套 Chromium 与 Node 运行时）
- 本轮不做移动端原生壳；手机网页与 PWA 离线另见 07
- 当前解码仍在 WebView；后续全 Rust 图像管线遵从 00 §7.3，未在本轮实现

## 普通目录与 Pixcall 元数据（2026-10-29）

Phase 2 的哈希路径与原件迁移性能数据是历史记录；新写入以本节、07 和 ADR 0002 为准。

- 新原件保存为收藏集同名文件夹下的正常文件名；保留嵌套和空文件夹，目录筛选包含子目录。支持普通文件保存，未支持预览的类型仍能在电脑文件夹定位。
- 同名文件保护双方；带目录的相同哈希允许多个文件位置。本地管理版不再提供旧格式自动迁移或旧原件整理入口；旧目录不会被自动清理。
- Pixcall 使用非 C 盘数据库/WAL 快照，跳过废纸篓、删除后代、缺失/仅云端原件；保留标签组与颜色、描述、URL、评分、创建/修改时间，扫描错误明确显示。
- 元数据、导入标签和单项来源地址同事务写入；归档、撤销及重扫改名同时迁移映射，重复导入保留已有本地描述、URL 和评分。描述、URL、评分、目录和九色代表索引已接搜索/筛选与详情。原件归档、软删除与撤销持久化；当前素材回收实际移动原件，预览恢复保留同名双方，中断日志可重放。

## 已复核：`tauri dev` 的窗口没有 Tauri 运行时（2026-10-29 记录，当晚复核不复现）

**记录时的现象**：`pnpm desktop`（= `tauri dev`）打开的窗口里 `"__TAURI_INTERNALS__" in window` 为 **false**，
`isDesktop()` 判定失败 → 界面退化成浏览器模式：读的是 Vite fixtures/IndexedDB 缓存、
资料库相关按钮全部禁用、Rust 侧一行 `[ceas]` 日志都没有。

**2026-10-29 晚复核：不复现。** 用与打包产物相同的配置启动，再通过 WebView2 的 CDP 端口实测：

```powershell
$env:CEAS_CONFIG_DIR="<repo>\.cache\client-config"
$env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS="--remote-debugging-port=9223"
pnpm desktop
# 另开一个终端
curl http://127.0.0.1:9223/json/list     # → url: http://localhost:5173/
```

实测结果：页面原点 `http://localhost:5173/`，`typeof window.__TAURI_INTERNALS__` 为 `object`，
界面渲染出真实库（「我的参考库」），并成功完成一次 IPC 往返
（`watch_library` 返回 Rust 侧错误串「资料库会话已改变，请重试当前操作」—— 说明命令确实执行到了 Rust）。

**结论**：`tauri dev` 是正常的桌面运行方式，不必再用 `build --debug --no-bundle` 绕行。
先前那次很可能是看了浏览器里的同一地址（没有初始化脚本），或在页面加载完成前就判断。
**下次怀疑它坏了，先跑上面这条 CDP 检查**，不要凭窗口外观推断。

排查时若确实缺运行时，按这个顺序看：① CDP 里的 `location.href` 是否为 `localhost:5173`
（不是则 Vite 端口被占、起了 5174，而 `devUrl` 仍是 5173）；② 该目标是不是 `type:"page"`；
③ `tauri.conf.json` 的 `devUrl` 与 Vite 端口是否一致；④ 构建产物原点应为 `http://tauri.localhost/`。
