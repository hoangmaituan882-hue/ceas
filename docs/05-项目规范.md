# 项目规范

> 效力：本文件是硬约束。与其它文档冲突时以本文件为准。
> 适用：所有人、所有 AI 代理、所有提交。新增规则先改本文件，再改代码。

---

## 0. 三条底线

1. **不往 C 盘写任何东西**（缓存、临时文件、工具链、构建产物）。见 §9。
2. **不引第二套同类依赖**（第二个设计系统、第二个图标库、第二个动画引擎、第二个 ORM）。
3. **不跳过验收**：任何提交必须能通过 `node scripts/check-paths.mjs` 与设计断言。

---

## 1. 目录结构与依赖方向

```
repo/
├─ apps/               desktop（Tauri 壳 + React）/ web（后续）
├─ packages/
│  ├─ core/            领域模型、SQL、视图谓词（纯 TS）
│  ├─ views/           网格 / 画布 / 无限 三个渲染内核
│  ├─ ui/              设计系统：Arc 组件副本、token、图标、吉祥物
│  └─ shared/          类型、常量、工具
├─ src-tauri/          Rust 薄层与图标
├─ sidecar/            媒体处理（若启用）
├─ extensions/         浏览器扩展
├─ assets/brand/       品牌矢量与 PNG
├─ scripts/            环境、守卫、生成器
└─ docs/               方案与规范
```

**依赖只能向下，禁止反向与跨层：**

```
apps  →  views  →  core
  ↓        ↓        ↑
 ui  ──────┘    shared（谁都可以用，它谁也不依赖）
```

- `packages/core` **不得** import React、DOM API、Tauri API
- `packages/ui` **不得** import `core` 的查询逻辑（只接 props）
- `packages/views` 通过 `DataSource` 接口拿数据，不知道自己在桌面还是 Web
- `src-tauri` 不得包含业务规则（只做文件、解码、IPC 转发）

## 2. 命名

| 对象 | 规则 | 例 |
| --- | --- | --- |
| 目录、文件 | kebab-case | `item-grid/`、`check-paths.mjs` |
| React 组件 | PascalCase，与文件名一致 | `ItemGrid.tsx` |
| Hook | `use` 前缀，动词开头 | `useSelection` |
| 函数 | 动词开头 | `resolveLayout`、`indexAsset` |
| 布尔 | `is/has/can/should` 前缀 | `isOffline`、`hasLocalFile` |
| CSS 变量 | `--区域-角色` | `--bg-elevated`、`--text-2` |
| SQL 表 / 列 | snake_case，表名复数 | `collection_items`、`deleted_seq` |
| 读时视图 | `v_<表>_visible` | `v_items_visible` |
| IPC 命令 | `资源.动作` | `item.create`、`import.enqueue` |
| 图标组件 | 语义名，不叫库名 | `Icon.Canvas` 而非 `AkarFrame` |

中文只出现在注释、文档与界面文案里；标识符一律英文。

## 3. 代码

- TypeScript `strict` + `noUncheckedIndexedAccess` + `verbatimModuleSyntax`
- 禁止 `any`；不确定时用 `unknown` + 收窄
- 格式化与 lint 用 Biome，提交前自动跑
- 注释写**为什么**，不写**是什么**；解释取舍的地方必须留注释
- 一个文件一个主概念；超过 400 行先想拆分，超过 600 行必须拆
- 禁止 `transition: all`；禁止在渲染函数里创建新对象传给 memo 子组件
- 时间、随机、文件系统、网络只允许出现在 `core` 的边界层，视图层保持纯函数

---

## 4. 数据与 IPC

- 主键客户端生成 UUIDv7；时间戳一律 UTC 毫秒
- 删除是软删除：写 `deleted_seq`，查询走 `v_*_visible`，**禁止写时级联**
- IPC **不传 buffer**，只传 id、状态、标量；一万张导入时 UI 会不会假死就看这条
- 图片解码与缩放只存在一处（WIC + 单一缩放实现）
- 路径全程 `\\?\` 前缀，库根目录限制在浅层

## 5. 依赖引入

新增依赖前必须回答四个问题，写进 PR 描述：

1. 现有依赖能否覆盖？为什么不能？
2. 它承担的**唯一职责**是什么？会不会与已有库重叠？
3. 替代方案是什么？为什么不用更简单的做法？（体积只记录，不作为否决理由）
4. 谁维护、多久没更新、License 是否 MIT/Apache？

**第三方 CJS 包**：若依赖只有 `main`（无 `module` / `exports`），禁止直接 import —— 无法 tree-shake，会把整包打进产物（akar-icons 实测 +340KB）。做法是构建期提取，见 `scripts/gen-icons.mjs` 与 `docs/03` §6.1。

**禁止清单**（写死，不讨论）：MUI / Ant Design / Chakra、`@radix-ui/themes`、shadcn 官方组件集、`sonner`、第二个图标库、tldraw、react-spring、Drizzle、写时级联删除、客户端时钟定序。

**不设体积门槛**（2026-10-29 决定，见 [ADR 0007](adr/0007-drop-size-budget.md)）：
前端 gzip 总量与安装包大小都不作为取舍或验收条件。依赖按职责、维护成本与构建复杂度判断；
构建产物大小在交付说明里记录实测值，只作趋势观察，超了不构成问题。

## 6. 设计执行

- 一切视觉值来自 token（`docs/01-设计规范-v2.md`）；禁止 hex 与 px 字面量
- 视觉规范分三层：**不变量（CI 管）→ 密度（派生）→ 主题（可换）**；改主题数值不需要改 CI
- 密度是系数 `D`，行高、gutter、字号、图标必须**一起变**，不允许只改行高
- 圆角只允许 4 / 6 / 10 / 18；间距只允许 4 / 8 / 12 / 16 / 24 / 32 / 48
- 动效时长只允许 140 / 200 / 280ms；同时动画属性 ≤ 2；只动 transform / opacity / filter
- 重排序只用 FLIP，同时参与动画的节点 ≤ 48；**虚拟列表内禁用 `layout`**（见 01 §5.3）
- 共享元素过渡（缩略图 → 详情）用手动 FLIP；**虚拟化或可滚动容器上禁用 `layoutId`**
- 动画包名统一 `motion`（import `motion/react`），禁止出现 `framer-motion`
- Tailwind 只写布局类，禁止 `bg-* / text-* / rounded-* / shadow-*`
- 图标只能从 `packages/ui/icon.tsx` 取；禁止直接 import `akar-icons` 或 `lucide-react`
- 三个页面的截图基线（网格 / 详情 / 过片）任何变化需人工确认

## 7. 提交与分支

- 分支：`feat/…`、`fix/…`、`chore/…`、`docs/…`；主干 `main`
- 提交信息：Conventional Commits，中文正文可，类型必须英文
  ```
  feat(grid): 加密度档位与行高联动
  fix(import): 暂停后恢复时重复入队
  ```
- 一次提交只做一件事；格式化与重构不和功能混在一起
- 禁止 `--no-verify`；禁止 force push 到 `main`
- 合并前必须：路径守卫通过、设计断言通过、截图基线已确认

## 9. C 盘禁令

**目标：除了系统组件，任何由本项目产生的东西都不落在 C 盘。**

### 9.1 会被默认写到 C 盘的东西

| 写入者 | 默认位置 | 重定向方式 |
| --- | --- | --- |
| Windows 临时文件 | `%LOCALAPPDATA%\Temp` | `TEMP` / `TMP` / `TMPDIR` |
| npm 缓存 | `%LOCALAPPDATA%\npm-cache` | `.npmrc` 的 `cache` |
| pnpm store | `%LOCALAPPDATA%\pnpm\store` | `.npmrc` 的 `store-dir` |
| Cargo registry / git | `%USERPROFILE%\.cargo` | `CARGO_HOME` |
| Rustup 工具链 | `%USERPROFILE%\.rustup` | `RUSTUP_HOME` |
| Playwright 浏览器 | `%LOCALAPPDATA%\ms-playwright` | `PLAYWRIGHT_BROWSERS_PATH` |
| pip 缓存 | `%LOCALAPPDATA%\pip` | `PIP_CACHE_DIR` |
| Cargo 构建产物 | 仓库内 `target/` | 已在 E 盘，无需改 |

### 9.2 落地方式

- 仓库级配置：`.npmrc`（已提交，含 cache / store-dir / state-dir）
- 会话级环境：`scripts/env.ps1`（PowerShell）或 `scripts/env.cmd`（cmd）
  ```powershell
  . .\scripts\env.ps1      # 每个新终端执行一次
  ```
- 所有缓存集中在 `E:/123pan/AI xianmu/ceas/.cache/`，已在 `.gitignore`

**编码坑（已踩过一次）**：`env.ps1` 必须存成 **UTF-8 with BOM**。Windows PowerShell 5.1 对无 BOM 文件按 ANSI 解码，中文注释的尾字节可能吃掉换行符，把下一行赋值并进注释里 —— 表现为「脚本跑完了，但 TEMP 没变、也不报错」。`env.cmd` 保持**纯 ASCII**，因为 cmd.exe 用 OEM 代码页解码。

### 9.3 验证

```bash
node scripts/check-paths.mjs
```

退出码 0 才算通过。它会检查环境变量、`.npmrc`、以及仓库配置里是否出现 `C:\`。

### 9.4 无法重定向的例外（写进这里，避免反复争论）

- **WebView2 Runtime**：系统级组件，由 Windows 安装
- **MSVC 生成工具 / Windows SDK**：编译 Rust 必需，系统级
- **Windows 自身的日志与事件**：与我们无关

判断标准：**是我们下载/生成的文件，还是系统组件**。前者一律重定向，后者记录在此。

### 9.5 新机器上手

1. 克隆到 E 盘（或其它非系统盘）
2. `. .\scripts\env.ps1`
3. `node scripts/check-paths.mjs` 必须通过
4. 再装依赖：`pnpm install`

## 11. AI 协作规则

团队以 AI 为主，这些规则等同于人：

1. **不扩大范围**：只做被要求的事。发现旁边有问题，写进交付说明，不要顺手改。
2. **不擅自升级依赖、不改规范、不改设计 token**。需要改，先提出来。
3. **改完必须自检**：`check-paths.mjs` + 设计断言 + 类型检查，三条都过才算完成。
4. **交付要带证据**：改了哪些文件、跑了什么命令、结果是什么。不说「应该可以」。
5. **不确定就问**，不要用合理猜测填空（尤其是产品决策与视觉判断）。
6. **每轮结束写记忆**：做了什么、为什么这么决定、留下什么未决项。
