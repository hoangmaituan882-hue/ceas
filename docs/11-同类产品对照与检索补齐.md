## 1. 三家的定位差异（决定我们该学谁）

| | Eagle | Pixcall | Billfish |
| --- | --- | --- | --- |
| 定位 | 设计素材库，**功能最全的付费标准** | **云端同步** + 多端 + AI 分析 | **免费**、开放目录、性能优先 |
| 库的形态 | 自有 `.library` 包 | 目录 + 自带数据库 + 云端 | **与资源管理器文件夹同步**，非侵入 |
| 强项 | 智能文件夹、十多个筛选维度、重复扫描、标注、Action 工作流、格式覆盖 | 云同步、mini 常驻、插件生态、AI（云或 Ollama/LM Studio）、聚合搜索 | 原生 C++ 性能、三视图（列表/画廊/沉浸）、以图搜图、重复检测、字体预览 |
| 短板 | 付费、库是私有包、迁移靠 eaglepack | 云依赖、AI 要额外付费 | 功能深度弱于 Eagle，UI 粗糙 |

**结论：功能深度学 Eagle，目录模型学 Billfish（其实我们已经在做），云与 AI 只学接口形态、不学它的依赖。**

我们与他们最本质的差别不是功能表上的一行，而是：**库就是一个文件夹，备份 = 拷贝目录，随时可以拔掉软件走人。**
三家里只有 Billfish 接近这个模型，但它仍需要"导入建库"；我们连这一步都没有。

## 3. 缺口排序（按"是否影响每天打开它"）

### P0 · 不做就等于没有检索

**3.1 保存的筛选（智能文件夹）** —— 三家都有，我们只有一次性查询。
用户每天真正要看的是"未整理的""最近 7 天""蓝色参考""带待办标记的"，而不是重新勾一遍筛选器。
实现上它只是把 `ItemFilters` + 搜索词 + 排序存成一个命名条目，但**这是从"能查"到"每天用"的分水岭**。

**3.2 检索维度补齐四项**：尺寸区间、文件大小区间、格式、所属收藏集。
现有 `ItemFilters` 有 12 个维度却少了这四个最常用的；`countFilters` 的模型可以直接扩。

**3.3 多标签组合**。现在 `tag` 是单值，而设计师的真实检索是"参考 + 赛博 + 未评级"。

**3.4 空格快速预览**。Eagle 的标志性手感：选中 → 空格 → 大图 → 方向键切换 → 空格退出。
成本极低（复用 DetailOverlay 的图源），感知极强。我们现在的双击+遮罩偏重。

### P1 · 决定"能不能替代 Eagle"

**3.5 PSD / PDF / 字体 缩略图。** 这是设计师最容易一句话否掉我们的地方——"我的 PSD 呢"。
至少在"能导入、有缩略图、能预览"这条线上给出降级路径：解不出就显示占位 + 类型图标 + 可在外部打开，
而不是导入失败。

**3.6 重复 / 相似扫描与合并界面。** 我们只在导入时按哈希去重，没有"扫描一遍已有的库"和"合并两组"。
Eagle 的合并会保留双方的标签并集，这个细节值得照抄。

**3.7 批量重命名 / 批量移动。** 导入 Pixcall 后第一件事往往是"把这些名字理一理"。

**3.8 随机 / 沉浸浏览。** 成本低，对"灵感库"这个用法很有效；我们的画布视图已有一半基础。

### P2 · 需要新依赖，别现在做

**3.9 语义 / 以图搜图**：要么上 embedding 模型，要么接 Ollama。先做 3.1–3.4，
把"确定性检索"做扎实，语义检索是锦上添花，不是地基。

## 4. 明确不抄的四条

| 不抄 | 理由 |
| --- | --- |
| 插件生态（Pixcall） | 插件需要稳定的宿主 API 与版本承诺，我们连 1.0 都没到；先把核心做对。 |
| 云同步（Pixcall 卖点） | H3 再说。它是成本中心，且不产生差异化——我们的差异化在本地。 |
| 聚合搜索（一次搜 10 个网站） | 依赖他人站点的抓取，版权与稳定性都不受控。 |
| 内置标注编辑器（Eagle） | 在图上画箭头是另一个产品（评审工具）。真要做，先接系统截图/外部工具。 |

## 5. 我们真正的差异点（别在补齐时弄丢）

1. **库即文件夹，没有"导入建库"这一步**。用户可以把库丢进 NAS、丢进网盘、用 git 管，甚至不用这个软件也能取素材。
2. **过片（收件箱清零）**。三家都没有"把收件箱清空"这个仪式，它们只有"一个越来越大的库"。
   这是唯一能形成习惯的机制，也是留存的来源。
3. **删除/回收/恢复都是真文件操作**，不是数据库里的一行标记（见 ADR 0005 / 0008）。
4. **不锁定**：没有私有库格式，没有必须联网的账号。

补齐 P0/P1 的过程中，凡是会破坏这四条的做法都要停下来重新想——
比如"为了做相似图而把缩略图搬到私有数据库"就是不值得的。

## 6. 建议的下一步顺序

1. 保存的筛选（3.1）+ 检索四项（3.2）+ 多标签（3.3）—— 一起做，都改 `ItemFilters` 与查询面板。
2. 空格预览（3.4）—— 独立小改动，见效快。
3. PSD/PDF/字体缩略图（3.5）—— 需要先定"解不出来时怎么办"，属于格式矩阵那一轮。
4. 重复合并（3.6）、批量改名移动（3.7）、随机（3.8）。
5. 语义检索（3.9）最后。
