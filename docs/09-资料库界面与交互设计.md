# 资料库界面与交互设计

> 2026-10-29 · 用户已明确“开工”。本文件是 08 §5.4 的本地阶段设计交付，独立交互预览在 [library-management.html](design/library-management.html)，示例数据不读写资料库。

## 页面与返回路径

欢迎页使用居中 idle 吉祥物、标题、三项并列入口、稍后设置。最近库管理页使用整页列表，当前项以边界和文字标明；卡片展示名称、完整路径、状态和操作。创建、改名、迁移与重新定位使用同一整页表单框架，返回管理页；不连续叠放模态。

| 页面 | 主动作 | 次动作 | 退出 |
| --- | --- | --- | --- |
| 首次欢迎 | 新建、打开、导入 | 稍后设置 | 未配置管理页 |
| 管理页 | 打开选定库 | 新建、改名、迁移、重新定位、移除记录 | 已有当前库时返回工作区 |
| 创建 | 创建并打开 | 空目录/已有目录、选择位置 | 保留草稿，取消不建库 |
| 改名 | 保存名称 | 同时改根文件夹名 | 取消保留原状态 |
| 迁移预检 | 开始迁移 | 选择目标父目录 | 取消不搬文件 |
| 迁移任务 | 查看阶段 | 停止/重试/收起 | 收起回管理页，任务继续 |
| 位置不可用 | 重新定位 | 重试、打开其他库 | 保留原库登记 |
| 引导 | 下一步 | 上一步、跳过此步、结束 | 恢复原工作区或管理页 |

## 状态与交互合同

- 名称/路径错误在字段附近显示原因，保留输入；预检中禁止重复提交。选择目录取消保持原表单。
- 打开前只探测；普通目录提示原地建索引，Pixcall 目录进入来源导入，损坏元数据进入错误状态。失败不替换当前工作区。
- 无库、空库、位置失效分别使用不同标题和主动作；读取数量期间显示正在读取，不填零。
- 拖放落点跟随当前位置，不由用户先选目标：**单个文件**落到收件箱（或当前收藏集）；**文件夹始终保留层级** ——
  在「全部素材」/标签/搜索下，顶层目录成为收藏集、收件箱不增加；收藏集内则落到该收藏集并保留子目录。
  回收站不接收并说明原因；拖到侧栏某个收藏集上时以被拖到的那个为准。
- 批量拷贝走无感：不弹模态、不抢焦点、不要求先点开始，进度只在顶部状态行，完成后一次轻提示；
  失败项进文件问题面板而不是弹窗。
- 改显示名默认不改文件夹；勾选改目录时展示最终路径。当前库名称入口沿用面包屑区域，保留居中三视图胶囊和右侧工具位置。
- 迁移显示准备/复制/校验/激活/完成阶段和实际文件进度。提交阶段不能停止时说明原因；失败展示原/目标位置和重试入口。旧副本不自动清理。
- 引导进度独立于文件操作，逐项可跳过；再次打开不会重复创建或导入。结束时根据是否有有效库返回相应界面。
- Esc 和页面返回仅关闭可关闭的表单/面板，不隐含停止任务。真正停止任务有独立按钮，提示已完成部分和原文件保留情况。
- 初始焦点落在页面标题后的第一个操作；字段出错定位相应字段；回到工作区恢复调用入口焦点。状态文字用克制的 aria-live，不逐帧播报。
- CSS 与原型共用现有主题/密度 token，图标从现有出口取，吉祥物遵循 04。明暗、长路径、三档密度与键盘同样验收。

### 主窗口采集（2026-10-29 已接生产接口）

- 拖入期间工作区顶部提示“松开以复制到「名称」”，有真实目录时同时显示路径；文件夹保留层级。
  侧栏目标用虚线环标明，当前导航选中保持不动。离开窗口/放下后反馈退出，不抢焦点。
- 回收站内容区域提示“回收站不能导入”；详情或管理面板打开时要求先关闭；忙碌时说明正在处理文件。
- 资源管理器复制文件后 Ctrl+V 使用相同落点。编辑框/可编辑区域保留正常粘贴，模态中不触发后台采集。
- 同名目录保留双方；导入失败保留来源文件，问题面板可重试单文件、打开来源文件夹。
  目录准备完成后停止会保留已建立的空目录，不隐式回滚原件。
- 生产事件/原件/SQLite 联调与明暗三密度反馈证据见 [ADR 0009](adr/0009-window-acquisition.md)。
  本轮没有人工模拟资源管理器鼠标拖放，不把受控事件测试称为系统手势全项验收。

## 文件变化与回收恢复（本地文件阶段）

工作区顶部原有一行常驻的“文件核对”状态行（旧称）（通知可用/周期核对、阶段、待处理数量）。**该形态已被下节取代**，本段其余内容仍有效：进入问题面板查看缺失、不可读、复制尚未稳定、同内容歧义和恢复任务错误。**外部删除已改为跟随进回收站**（[ADR 0008](adr/0008-follow-external-delete.md)）：核对确认不存在的项直接软删除并到回收站，标「原件已不在磁盘」，人工信息保留；不可读、被占用、移动盘未插只标状态，绝不当作删除。

- 文件通知合并后与目录事实比对；启动、回到窗口和周期兜底。先做两次观察，仍变化的文件留待下次，不把复制中的半成品加入素材库。
- 文件身份优先关联外部改名；没有可靠身份时只有双方唯一的完整哈希候选才关联。歧义显示候选，用户可以选库内文件关联，或把新文件保留为独立素材。
- 应用回收把原件移到 `.ceas/trash`，保留原名字/相对层级和持久操作记录。素材文件与整目录回收都已交付（整目录走祖先墓碑，见下节与管理抽屉）。
- 恢复按钮打开预览，显示原位置与同名处理；可保留双方、指定相对收藏集或取消。恢复不覆盖已有文件，取消不移动文件。任务错误显示源/目标与重试入口；仅符合前置条件时允许取消尚未移动的操作或改目标继续。批量同名目标预览使用各自可用名称。
- 问题面板沿用现有 token/表单/焦点环，Esc 返回原入口；状态行 aria-live 只播报阶段或问题数量变化。

### 内容修改在界面上的表现（设计 · 待开工）

文件在外部被编辑保存后，**同一素材原地更新**（[08 §10](08-资料库管理完整方案.md)、
[ADR 0008](adr/0008-follow-external-delete.md)）。界面上它必须"看不出发生过什么"：

| 时刻 | 表现 |
| --- | --- |
| 更新成功 | 缩略图原地替换，不弹提示、不算新增、不进回收站；标签/描述/评分/位置不变 |
| 新缩略图还没算好 | **保留旧缩略图**，不要先清空 —— 闪一下白比晚 300ms 难看得多 |
| 内容解不开 | 先保留旧缩略图 + 一条角标「无法解码」，记录不消失；用户选「按普通文件保留」后改按普通文件显示 —— 旧缩略图已经不代表这份内容，不能继续挂着 |
| 详情页正打开着 | 不静默换图，顶部一条：`磁盘上的内容已更新 [刷新]` |
| 正在播放该视频 | 不打断播放；下次打开生效 |

- 更新**不改变排序**（`created_at` 不动），"最近修改"若将来出现，用 `modified_at`。
- 更新失败不产生"待处理项"以外的噪音：它进文件问题面板，但**不弹窗**。
- 批量修改（比如一次替换 200 张）按同一规则逐条更新，顶部只出现一次「正在更新 N 项」。

### 回收站视图与彻底删除（已实现）

现在回收站只有「恢复」一个动作：`BatchBar` 在 `trashMode` 下把「删除」换成「恢复」。
这意味着**回收区只进不出**，删再多的图磁盘空间也不会变 —— 用户会认为软件在骗他。

**两种来源，能力不同，必须分开显示：**

| 来源 | 怎么来的 | 原件在哪 | 能恢复吗 |
| --- | --- | --- | --- |
| 应用回收 | 在 Ceas 里删除 | `.ceas/trash/<任务>/<原相对路径>` | 能，完整还原 |
| 磁盘删除 | 在资源管理器里删掉 | 不在（没有副本） | **不能还原字节**，只能重新定位或关联 |

所以回收站列表每一行都要带来源标签；`磁盘删除` 的行显示「原件已不在磁盘」，
它的"恢复"打开的是重新指认面板，而不是现有的恢复预览。

问题面板里 `pending`（内容更新未完成）、`decode`（内容解不开）与 `unreadable`（读不到）都提供**「忽略此文件」**：
文件坏了、被占用、是别的软件的临时文件时，用户需要一个"别管它了"的出口 ——
否则这两个状态只能靠关掉面板来回避，下次检查又原样出现。

`decode` 另给一条**「按普通文件保留」**：哈希按磁盘重算、类型降级为普通文件、整理信息不动。
没有它，一张被改坏的图只有"反复重试"一条路，而重试永远不会成功。

整目录消失只出一条汇总，两个动作：

```
收藏集「参考」在磁盘上已不存在（80 个文件）
[移入回收站]  [重新定位…]
```

「重新定位…」打开目录选择器，选**它现在所在的文件夹**，后端把它收回库内原位置
（库就是普通文件夹，收藏集路径不是可以随手改的标签）。同盘瞬时回位；跨盘复制并校验，
原目录保留，结果里说明"已复制 N 个文件，原目录仍保留"。收回后核对按同路径同哈希复活每条记录。

「磁盘删除」项的恢复面板不提供"恢复"，只有两条出路（文案据实说明原因）：

```
3 项没有可还原的原件
这些文件是在资源管理器里删除的，磁盘上已经不存在，回收区里也没有副本……
[把整理信息合并到…]  [彻底删除记录]  [取消]
```

合并只对单条开放（合并到哪一份是个具体选择，不是批量操作）。

**动作清单（回收站视图，多选后出现在批量条 / 右键菜单）：**

| 动作 | 行为 | 前置 |
| --- | --- | --- |
| 恢复… | 现有流程：预览原位置与同名处理，不覆盖 | 原件仍在 `.ceas/trash` |
| 彻底删除… | 删除回收区里的原件 + 记录（含标签关系） | 二次确认 |
| 清空回收站… | 全部彻底删除 | 二次确认，显示总大小 |

**确认文案要写出后果与收益**，不能只说"确定吗"：

```
彻底删除 12 项？
这些文件将从回收区移除，无法恢复；同时释放 1.8 GB。
```

```
清空回收站？
将永久删除 340 项，释放 12.4 GB。此操作无法撤销。
```

- 彻底删除**不删磁盘上的其他副本**：回收区里那一个就是唯一被删的对象。
- 若有**未完成的恢复任务**指向该项，先禁用并提示"该项目还有未完成的恢复操作"。
- 清空同样受"目录操作进行中"约束（与回收一致）：正在移动文件时不给做。
- 释放体积按**实际文件字节**求和，不含缩略图与数据库；数字用 `tabular-nums`。

**与文档 §11 的关系**：08 §11 写的是"首版不**自动**永久删除、不按时间 GC"，
手动彻底删除不属于那条限制。这一节补的就是手动路径 —— 没有它，"删了但空间没变"无法解释。



### 检查文件变化：常态零存在（2026-10-29 已定）

**决定三件事**：正常时界面不出现任何东西；有问题才出现；手动检查放进设置。术语统一为
**「检查文件变化」**，不再用"核对"。

**它是什么。** 库就是普通文件夹，任何软件都能往里加、改、改名、删。应用要定期把"磁盘事实"和
"数据库记录"对一遍账：能对上的（比如在资源管理器里改了名）直接关联；对不上的（同内容多个候选、
文件消失、读不出来）攒成待处理项。**这是基础设施，不是功能** —— 用户不需要理解它。

**它是自动的。** 打开软件、窗口重新获得焦点、收到系统文件通知、以及周期兜底，四个时机都会自己跑一遍；
设置里的按钮**只是兜底**（怀疑库和磁盘不同步时手动确认一次），不是日常流程。
所以界面上任何"请你去检查"的语气都是错的。

#### 出现规则

| 状态 | 界面 |
| --- | --- |
| 正常（无待处理项） | **什么都不渲染**（零高度，不占位） |
| 有 N 个待处理项 | 工作区顶部一行：`3 个文件和库不一致` + `查看` |
| 单次检查超过 10 秒 | 一行：`正在检查文件变化…` + `停止`（01 §6.5 的 10 秒阈值） |
| 检查本身失败（权限/IO） | 一行：`检查未完成：<原因>` + `重试` |

- 用**行内提示**而不是模态弹窗：文件不一致不是"必须马上处理"的事，弹窗会打断正在做的事。
  真正紧急的情况（原件丢失导致打不开）在详情页就地说明。
- 只在**待处理项数量变化**时用 `aria-live="polite"` 播报，不在每次扫描时播报。
- 正常态不显示"上次检查时间"——它只放在设置里。一行永远显示"没事"的状态栏，
  第一次真出问题时反而不容易被注意到。

#### 入口

| 位置 | 内容 |
| --- | --- |
| 设置 ▸ 文件 | 「检查文件变化」按钮 + 上次检查时间与结果 + 通知降级说明 |
| 问题提示行 | `查看` 打开问题面板（复用现有 FileIssues） |
| 命令面板（后续） | 「检查文件变化」；`cmdk` 尚未引入（02 §6 排在 M2），本轮不做 |

设置里的那一行是**唯一的手动入口**，所以它必须写清结果，不能只有一个按钮：
`上次检查：今天 14:32 · 未发现问题` / `发现 3 项待处理`。

#### 文案

| 场景 | 旧 | 新 |
| --- | --- | --- |
| 术语 | 核对 | 检查文件变化 |
| 正常态 | 已核对 · 文件通知已启用 · 无待处理项 | 整行不显示 |
| 有问题 | N 项待处理 | N 个文件和库不一致 |
| 进行中 | 正在核对文件 · 文件通知已启用 | 仅超 10 秒时：正在检查文件变化… |
| 通知降级 | 文件通知已启用 / 周期核对 | 正常不显示；不可用时「系统通知不可用，已改为每 30 秒检查」 |
| 拦截（删除时） | 正在核对或导入，请完成或停止后再回收文件 | 按真实原因二选一：「正在检查文件，稍后自动完成」/「正在导入，先停一下」 |

#### 命名：两处都落定

收藏集面板里那个按钮做的是**另一件事**（重新读取磁盘目录、把新文件夹变成收藏集），
现在叫「核对目录」。两处"核对"并存会被当成同一个功能，因此：

- 文件侧：**检查文件变化**（自动进行，手动只是兜底）
- 目录侧：**重新读取目录**（明确是"再读一次磁盘"，不是"比对"）

动词不同、对象不同，一眼能分开。验收脚本里 `check-collections.mjs` 依赖旧按钮名，
开工时要同步改成新名字（`CollectionManager.tsx` 一处按钮文案 + 脚本一处断言）。

> 本节已定，代码尚未改动 —— 按用户要求，等"开工"指令后再实现。

本阶段证据：`pnpm check:files-ui` 12 组实际 Rust/SQLite 联调，`pnpm check:files-native` 使用独立 Tauri/WebView2、真实 IPC，检查通知、缺失、恢复、明暗三密度和焦点。前者报告 `.cache/tmp/file-coordination-latest.json`，后者 `.cache/tmp/file-native-latest.json`；截图 `file-missing.png`、`file-ambiguity.png`、`file-restore-preview.png` 和 `file-native-*.png`。设计合同中的完整长任务历史、字段定位和整目录恢复仍为待办。

## 稳定收藏集与整目录操作（本阶段交互合同）

侧栏增加“管理收藏集”。面板展示稳定收藏集的完整位置、状态与素材数量，提供创建、改名/移动、回收和已回收收藏集入口；回收站工作区同时显示收藏集回收入口。改名或移动输入库内相对位置，拒绝移入自己、后代、系统目录或已有目标，大小写改名走受控暂存。

回收先预览对象路径、实际文件/空目录数量与影响说明，明确整个文件夹会进入库内回收区；确认之前不移动。只标记所选祖先，后代通过读取规则隐藏，保留素材、标签和各自已有的回收标记。恢复预览完整目标，同名自动保留双方，可改位置或取消，不合并已有目录。

外部目录改名/移动保持目录身份及素材关系；外部目录缺失显示缺失状态，保留整理信息。未完成目录任务有独立记录，展示源、暂存和目标，提供恢复重试、符合条件时取消或另选目标；处理中阻止重复提交并参与切库屏障。面板使用既有 token、焦点约束和 Esc 回焦。备份/修复作为下一子阶段，不在本阶段提供空入口。


验收脚本默认连 `http://127.0.0.1:5174`（隔离服务，与 `vite.config.ts` 的 5173 分开）；原生宿主默认 CDP `127.0.0.1:9223`。两者都可覆盖：`APP_URL=... CDP_URL=... pnpm check:collections-ui`。

### 管理收藏集：抽屉形态与文案（2026-10-29 修订）

**形态从居中模态改为右侧抽屉。** 遮罩只做轻微压暗，网格仍在视野里 —— 管理目录不是"进入另一个页面"，
而是一边看库一边整理。面板宽度按 `--row-target` 推算，高度满屏，行高跟随密度。

**列表是树，不是卡片。** 每行：状态点 + 名称（可点）+ 可选状态词 + 悬停出现的操作。

- 状态点用颜色区分：可用（实心绿）、目录缺失（灰）、暂不可读（红）、已回收（空心）。
- **只有非"可用"才显示状态词**：一屏五个"可用"只是噪音，点已经说明了。
- **名称可点**：直接跳到该收藏集并关闭抽屉。否则要先关抽屉、再回侧栏找一次 —— 那才是"有存在感"的交互。
- 操作悬停或键盘聚焦才出现（`:focus-within`），行本身不整行可点，避免误触。
- 层级只做缩进、不折叠：这里是"看清全貌"的地方，藏起子集反而找不到。

**文案以"少解释、说结果"为准**（旧 → 新）：

| 旧 | 新 | 理由 |
| --- | --- | --- |
| 改名或移动 | 改名 / 移动 | 斜杠比"或"更短，也更像两个并列动作 |
| 回收整个收藏集 | 回收收藏集 | "整个"由预览里的数量说明，不必写在按钮上 |
| 预览恢复收藏集 | 恢复 | 恢复本身有预览步骤，按钮不需要预告 |
| 预览操作 | 查看影响 | 说明点下去会发生什么，而不是描述按钮行为 |
| 取消本次操作 | 取消 | "本次"没有信息量 |
| 确认回收整个收藏集 / 确认恢复收藏集，保留双方 / 确认改名或移动 | 确认回收 / 确认恢复 / 确认移动 | 后果已在预览里逐条列出 |
| 待恢复的收藏集任务 | 未完成的目录操作 | 说的是事实，不是"待恢复"这种内部状态词 |
| 重试收藏集任务 / 取消尚未移动的目录任务 / 使用新位置继续目录任务 | 重试 / 取消（尚未移动）/ 用新位置继续 | 长句里的限定条件移到预览里 |
| 核对目录 | 重新读取目录 | 与文件侧的「检查文件变化」区分：那是对账，这才是重读磁盘 |

**动效与排版（按 01 执行）：**

- 面板进出用弹簧（`stiffness 320 / damping 32`，位移 24px），遮罩只做 200ms 透明度；
  减少动效时**取消位移、只留淡入**（01 §1.6 / §5.2）。
- 中文文本一律 ≥ 12px：紧凑档的 `--font-sub` 是 11px，中文不能用它；数值（计数）才用。
- 计数用 `tabular-nums`，避免数字变化时宽度跳动（01 §4）。
- 标题复用既有 `.panel-head h2`（15px / 500），不另造字号 —— 之前标题与正文同为 13px，没有层级台阶。
- 忙碌提示延迟 300ms 才出现（01 §6.5），否则快速操作只会闪一下。

**待补规范**：抽屉目前贴边、不做圆角，而 01 只定义了"面板/对话框 10"。抽屉是本次新增的形态，
是否给它独立的圆角与宽度规则，需要先改 01 再实现，不在这里私自决定。

**两个行为修正：**

1. 打开面板不再把应用标记为"正在导入"。此前它借用导入标志来暂停自动核对，
   副作用是导入入口被冻结、关面板时还会复写这个标志。暂停核对本来就由"面板打开"这一个状态负责。
2. 回收按钮标记为危险操作：平时不吵，悬停该按钮时才变红。

本阶段已落地：管理收藏集与回收站入口，真实目录预览、确认、取消、任务重试/取消/改址。面板打开时暂缓自动核对，关闭后继续；取消表单或完成操作时焦点返回相应目录操作，目录不在当前页时回到关闭按钮。列表先显示 100 项，继续加载更多。8 组共享原生联调与真实 Tauri 的明暗三密度/键盘/错误检查报告为 `.cache/tmp/collections-latest.json`、`collections-native-latest.json`。截图 `collection-move-preview.png`、`collection-restore-conflict.png`、`collection-native-*.png`。

### 侧栏收藏集右键菜单（设计 · 待开工）

**触发**：右键侧栏任一收藏集行；`Shift+F10` 或菜单键同样打开。

**右键不改当前视图。** 网格里右键素材会顺手把它变成当前选中（跟系统习惯一致），但侧栏不这样做 ——
右键一个收藏集却把你正在看的列表切走，是很突兀的副作用。改为给目标行一个**弱于选中**的上下文高亮
（`data-context`），只表示"菜单在操作它"。

**菜单（普通状态）：**

```
打开                    ↵
在资源管理器中打开
────────────────
新建子收藏集…
改名 / 移动…
复制路径
────────────────
回收收藏集…             ← 危险色，单独一组
```

**侧栏不列回收区里的收藏集**（它们只在管理抽屉的「回收站」页签中出现），所以本菜单不设"恢复"分支。
在抽屉里恢复，不要为了右键菜单把回收区搬进侧栏 —— 那会让每天看到 200 行的侧栏变成 260 行。

#### 每一项的依据（不放假按钮）

| 项 | 行为 | 依赖的现有能力 |
| --- | --- | --- |
| 打开 | 工作区切到该收藏集（等价左键） | 现有 `onPick` |
| 在资源管理器中打开 | `explorer <库根>/<相对路径>` | `reveal_in_explorer` 已存在（设置页在用） |
| 新建子收藏集… | 打开新建表单，名称带 `父/` 前缀 | `create_library_folder` + `ensure_collections` |
| 改名 / 移动… | 打开管理抽屉并进入该行的改名表单 | `directory_preview` / `directory_begin` |
| 复制路径 | 复制完整磁盘路径 | 前端拼 root + 相对路径，无需后端 |
| 回收收藏集… | 打开抽屉里的回收预览 | 同上（预览 + 确认） |

**为什么改名与回收都带省略号、都要进预览**：目录操作会移动真实文件，必须先看到"几个文件、几个目录、
有没有冲突"。一键直接动文件的菜单项，在这里是不负责任的。

#### 命名（已定）

菜单项叫 **「在资源管理器中打开」**，不用用户最初说的「打开为文件夹」——
后者会被读成"把这个收藏集变成文件夹"（它本来就是文件夹），而实际动作是"在系统里打开它"。

**「在上级文件夹中显示」不做**（`explorer /select,<path>`）。理由：侧栏菜单里已经能"打开"，
而复制路径 + 在资源管理器打开这两条已经覆盖了"我要去磁盘上看它"的意图；
再加一条只在父目录里选中它的项，是把系统右键菜单的惯例照搬过来，收益接近零、菜单却更长。
用户若真要定位父目录，`Ctrl+L` 一次就到位。

#### 标识：两种前缀，别直接当 UUID 用

侧栏给的 `id` 不是裸身份，**带前缀**，动作前必须归一：

| 运行形态 | 侧栏 `id` | 真实身份 |
| --- | --- | --- |
| 桌面（`isDesktop()`） | `collection:<uuid>` | 去前缀得到 `collection_store` 的 UUID |
| 浏览器预览 | `folder:<相对路径>` | **没有身份**，路径即身份 |

两个连带后果：

1. **浏览器预览下隐藏所有磁盘相关项**（在资源管理器中打开 / 新建子收藏集 / 改名·移动 / 回收），
   只留「打开」「复制路径」也一并隐藏（没有库根）。否则点了必然报错。
2. 改名/回收要用**裸 UUID** 去查抽屉里的 `CollectionRow`（它有 `state` 与 `path`），
   因为侧栏那份 `Collection` 类型没有 `state` 字段 —— 见下条。

#### 类型缺口：侧栏 `Collection` 声明里没有 `state`

`FolderCollection` 是 `{id, path, label, depth}`，但 `useLibraryFolders` 在桌面分支里**额外塞了 `state`**
（`state: row.state`），浏览器分支没有，于是这个值在类型上是"看不见"的。
禁用规则要用 `state`，就得先把这个字段补进类型（或让菜单直接从 `rows` 取 `state`，按裸 id 查）。

#### 禁用与原因

| 条件 | 结果 |
| --- | --- |
| 收藏集状态不是 `ready`（缺失 / 暂不可读） | 打开、在资源管理器中打开、新建子收藏集、改名、回收 全部禁用 |
| 存在未完成的目录任务 | 所有写操作禁用（读操作仍可） |
| 浏览器预览（无桌面运行时） | 除「打开」外全部隐藏 |

禁用的原因**写在菜单底部一行灰字**，不靠悬停提示（08 §5.4）：
`目录当前不可用，先「重新读取目录」` / `有未完成的目录操作，先去处理`。

#### 只有收藏集行吃右键

收件箱、回收站、标签、导入素材、设置这几行**不拦截**右键 —— 它们没有本菜单里的任何动作。
（WebView 默认菜单里那些"重新加载/检查"本来也没用，但拦截它需要另做一套"空白菜单"，
不值得为它破坏"右键只在有动作的地方有反应"这条一致性。）

#### 键盘与焦点

`↑ ↓` 移动、`Enter` 执行、`Esc` 关闭并把焦点还给那一行；打开菜单时焦点进入菜单第一项。
`Shift+F10` 依赖元素可聚焦 —— `rail-item` 是 `<button>`，天然满足。
菜单高度不超过视口，超出时上下滚动而不是被裁掉。

`data-context` 高亮在四种情况下清除：菜单关闭、执行任意项、点击别处、窗口失焦。
漏掉最后一条会留下一个"永远亮着"的行。

#### 明确不做

- **内联重命名**：磁盘改名要经过预览与事务，内联编辑会绕过这套保护；
- 导出该收藏集为 ZIP（导出功能尚未实现）；
- 「在新窗口打开」：单窗口是当前架构，不做假承诺；
- 「在上级文件夹中显示」（`explorer /select,`）：与「在资源管理器中打开」+「复制路径」重复，见上节命名说明；
- 「选中此收藏集内的全部素材」：可以做，但与菜单职责不同，留到批量选择那一轮。
