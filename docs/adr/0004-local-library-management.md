# ADR 0004：本地资料库管理实施

> 2026-10-29 · 用户明确“开工”后实施；范围为本地基础管理与部分 P2 管理任务。

## 背景

ADR 0003 和 08 定义了完整目标。当前需要先解决创建/打开混用、单路径登记、目录搬移后的空库误建和切换中的迟到写入，并让关键操作有真实 UI 与恢复证据。工程验证阶段不承担旧 Ceas 格式兼容。

## 选项

1. 沿用旧 settings、根目录数据库与自动升级，增加兼容分支。会保留入口歧义和双轨状态。
2. 先建立严格新格式和受检会话，管理动作共享文件/存储写入屏障，再逐阶段扩展文件协调和网络能力。

## 决定

采用选项 2，不新增依赖、不修改视觉 token。

- `.ceas/library.json` 保存 UUIDv7 和格式版本，`.ceas/library.db` 保存同一库身份及显示名。只有显式创建可以初始化；打开/读取不带 SQLite CREATE。旧格式原件及配置不自动改写。
- 非 C 盘运行配置登记多个库、当前库和引导；WebView profile、临时目录、任务记录一并重定向。库身份与路径独立。
- 原生边界持有单个当前库会话及独立 SQLite 写锁；请求携带会话代次和根位置。文件/数据库操作完整受检，切换前刷新待写；导入结束或停止收尾后才切换。
- SQLite 继续 WAL，当前新格式使用 synchronous FULL，增加写入持久性成本；不据此承诺真实断电零丢失。人工信息写入等待事务提交。
- 根目录改名经自有暂存目录；迁移采用复制、fsync、完整 SHA-256、源变化复核、目标数据库检查，再发布和登记。原副本保留，不自动删除。管理记录持久化，进程中断可识别发布/登记窗口；失败重试启动新任务，不冒称文件级断点续传。
- 列表 JSON 损坏保留原文并生成备份，进入可恢复管理页；任务记录损坏保留并报错。显示名登记失败时数据库事务回滚。
- UI 先交付独立原型与状态规格再接真实接口，欢迎沿用 idle 吉祥物。没有库也可管理和重看引导；素材工作区只接受有效会话。

## 代价

完整校验会增加复制和读盘时间，FULL 增加写入开销，旧副本及故障暂存会占空间。当前任务互斥且管理页保持打开，历史任务、暂存清理与备份 UI 尚待补。物理跨卷、移动介质和真实断电未实测，不能从同卷测试推定。

尚未实施完整监听/文件协调、稳定目录和标签关系、实际回收区、独立副本、原生 WIC 管线及 Linux/网页/PWA/ZIP。当前 File/URL 入口仍复用既有字节 IPC；后续应按 05 的路径/状态接口要求完成原生媒体边界，不能新增第二条解码管线。

证据与命令见 [08 §21.1](../08-资料库管理完整方案.md) 和 [09](../09-资料库界面与交互设计.md)。ADR 0001/0002 的旧布局和升级记录保留历史含义，当前入口和格式以本决定为准。
