# ADR 0003：资料库管理、统一辅助目录与同步边界

> 2026-10-29 · 设计基线。用户后续已明确“开工”；本地实施决定见 ADR 0004，本文的完整目标不代表全部代码完成。

## 背景

用户在普通文件夹方案基础上，要求可自定义位置/名称、多库共存、切换、改名、迁移、首次欢迎吉祥物、引导每步可跳过及以后重新查看，并要求补齐异常与恢复 UX。用户明确当前是工程验证阶段，不考虑旧版 Ceas 兼容，允许较大改动；目前只授权写完整方案。

现有创建/打开共用初始化、仅登记当前路径、路径失效后可能误建空库，不足以支撑完整管理流程。原件、人工信息和缓存需要有清楚边界，未来 Linux 同步与手机离线不能依赖桌面浏览器缓存。

## 选项

1. 保持路径即库身份和通用初始化，继续在设置中补按钮。无法准确区分打开、重新定位和新建，路径变化及失败恢复不可靠。
2. 先做服务器和双向编辑，再补本地库管理。增加冲突面，不能优先解决当前入口与迁移问题。
3. 先建立稳定库身份、统一辅助目录和管理任务，完整交付本地生命周期，再分阶段发布到 Linux 和手机离线。

## 决定

采用选项 3，完整合同见 [08 方案](../08-资料库管理完整方案.md)。

- 资料库保持普通原件目录，辅助数据归入 `.ceas`；回收区原件和人工信息属于需要保存的数据，派生缓存可重建。
- 库身份独立于显示名、目录名与路径；库显示名允许单独修改，根目录改名为明确可选操作；收藏集名称对应真实子目录。
- 创建、打开、原地建索引、导入、重新定位、迁移与独立副本分开；打开探测绝不创建缺失库。
- 应用可进入无库的欢迎/管理页，素材工作区需要有效库；引导每步可跳过且可重开，真实文件任务采用独立取消和恢复规则。
- 文件系统操作与数据库通过持久任务协调；切换/迁移/回收均需处理迟到请求、崩溃窗口和外部修改，不假设跨系统原子提交。
- 删除继续软删除和读时祖先谓词，不向后代级联写入删除标记；整库永久删除和自动 GC 暂缓。
- 本地优先，每库可选一个服务器目标，首版一个桌面写入源、网页和手机只读、桌面保留原件；NAS 共享盘直接活动 SQLite/WAL 不列为默认支持。
- 工程验证阶段不保留旧格式自动迁移/双轨兼容轨道；重建测试库是另一个明确动作，本次不执行。

## 代价

需要改造当前目录/模型和会话协议，并补充管理任务、文件协调与故障测试。稳定目录/标签 id、回收区和可恢复迁移增加实现工作；备份及跨盘迁移旧副本会占空间，应可查看并单独清理。

文件监听不保证捕获所有变化，须核对兜底；外部软件不遵守应用锁，迁移需检测变化并保留有歧义的数据。SQLite/WAL 对网络文件系统有约束，NAS 支持不能仅凭目录可选择就宣称完成。

本决定更新 ADR 0002 中后续布局/兼容实施方向，保留其普通原件原则及历史事实；ADR 0001 中事务、软删除和恢复原则继续适用。未改变工程硬约束、视觉 token 或依赖选择；实施授权来自用户后续的“开工”，当前落地边界见 ADR 0004。
