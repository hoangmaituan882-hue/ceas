# ADR 0008：外部删除跟随进回收站（复刻 Pixcall 方法二）

- 状态：已接受（2026-10-29）
- 影响范围：`file_reconcile`、`store_protocol`、回收站视图、问题面板
- 取代：`docs/08` §10「文件或目录消失 → 标记缺失，不直接变成删除指令」与原 §11「外部删除与应用回收分别显示」

## 背景

库就是普通文件夹。用户完全可能在资源管理器里删素材 —— 这既是正常操作，也是这个产品
"文件是你的"这一主张必然带来的后果。原先的设计是：核对发现文件消失后只标 `missing`，
素材留在库里、进问题面板，**不跟随删除**。

对照 Pixcall 后，它的两条删除路径各有确定结局：

| Pixcall | 结局 |
| --- | --- |
| 客户端删 | 磁盘同步删除 + 进废纸篓，可恢复 / 可彻底删除 |
| 在库文件夹里删 | 客户端跟随删除；未上云直接消失，已上云进云端废纸篓（"仅云端"） |

用户明确要求**复刻这种做法**：在文件夹里删掉的东西，应该在回收站里看得到，而不是变成
一堆永远处理不完的"缺失项"。

## 决定

1. **核对确认文件不存在时，跟随删除**：软删除（写 `deleted_seq`）并把 `ceas.file.<id>` 的
   状态记为 `missing`，条目进入回收站，标签、描述、评分、色样、来源全部保留。
2. **只有 `NotFound` 算删除。** `unreadable`、被占用、权限不足、移动盘未插一律不算 ——
   这类情况只标状态，绝不软删除。这是本决定唯一的安全边界，也是它唯一可能造成灾难的地方。
3. **批量消失要一次确认。** 单次核对里消失项超过阈值（默认 >20 项或 > 可见总数 10%）时
   不自动回收，改为一条汇总问题：「检测到 N 项在磁盘上消失，是否移入回收站？」。
   移动盘拔掉、网络盘断连、整目录误删都会命中这条。
4. **回收站里分区显示来源**：`应用回收`（原件在 `.ceas/trash`，可完整恢复）与
   `磁盘删除`（原件已不在，标注「原件已不在磁盘」）。
5. **"磁盘删除"项的恢复不是还原，而是重新指认**：提供「重新定位」与「关联库内文件」；
   做不到就明确告知，不用一个点了没用的"恢复"按钮掩盖事实。
6. **文件回来就复活**：撤销删除、移动盘重新插上之后，若原路径与完整哈希都与某条
   `磁盘删除` 记录一致，复活那条记录（保留人工信息），不新建素材。
   这一条与"upsert 不能复活墓碑"不冲突：那是重复导入，这是**文件事实回到原样**。

## 为什么不能完全照抄 Pixcall

Pixcall 的"已上云 → 进云端废纸篓 → 可恢复"依赖云端副本。单机版没有第二份字节，
文件在应用之外被删除后**不存在可恢复的原件**。所以：

- 记录可以恢复（元数据、标签、位置信息都在）；
- 字节不能恢复。

把这两件事混成一个"恢复"按钮，等于承诺一个做不到的结果。因此回收站必须**在进入时就标明**
这条是"磁盘删除"，恢复时走重新指认。这是复刻时唯一必须偏离的地方，也是不能省的地方。

## 与"内容修改"的关系（重要）

跟随删除之后，核对必须先判**内容更新**，再判**缺失**。同一个文件被编辑保存，
路径没变、文件身份没变、只有哈希变了 —— 如果先按"旧哈希的素材不见了"处理，
一次保存就会把用户整理好的素材推进回收站，同时新建一条空白的。

（现状：这条顺序**已经隐含成立** —— 计划层虽然会同时产出 match 与同路径 import，
但 `importer` 按路径命中旧行时会复用旧 id 并更新媒体信息，实际是原地更新。
本 ADR 把它写死成规则，避免将来重构时把顺序弄反。）

因此判定顺序固定为：

1. 身份/路径能对上、内容哈希变了 → **原地更新**
2. 对不上、也确实 `NotFound` → 跟随删除
3. 对不上、但仍可读 → 按新文件导入

第 1 条优先于第 2 条，与"删除要谨慎、更新要顺手"的直觉一致：误判成更新最多丢一条历史，
误判成删除会让用户失去整理成果。

## 代价

- **误删风险从"丢记录"变成"丢记录 + 要手动找回"**：跟随删除让"文件消失"这个事实
  直接改变库的可见内容，一旦误判（比如判成删除的其实是暂时不可读），用户会看到图消失。
  阈值确认与 `NotFound` 单条件是把风险压回去的两个闸门，缺一不可。
- **回收站语义变复杂**：两种来源、两种恢复能力，UI 必须说清楚，否则用户会以为所有项都能还原。
- **彻底删除的释放体积要分开算**：`磁盘删除` 项没有原件可删，体积按 0 计。

## 未做 / 后续

- 手动彻底删除与清空回收站（`docs/08` §11.2）尚未实现；
- 目录级消失的汇总提示（"收藏集「参考」在磁盘上已不存在"）尚未实现，目前会退化成 N 条单项；
- 阈值是否需要按库规模自适应，等真实大库数据再定。
