# ADR 0005：文件事实核对与可恢复的素材回收

日期：2026-10-29。状态：本地文件阶段已实施；完整 P2 仍有待办。

## 背景

普通目录允许第三方新增、改名、移动和编辑文件。仅靠导入映射会遗失改名后的人工信息；只写删除标记会使原件留在普通目录，并被下一次扫描重新收录。文件移动与 SQLite 事务也无法一次原子提交，需要把中间状态保留下来。

## 选项

1. 定时全部重导入，按文件名或内容相同直接合并。实现短，但同内容多副本和改名交换会错误归属。
2. 通知提示变化，事实扫描核对；纯 TS 决定候选，原生复核并持久化。应用回收使用可重放的文件操作记录。

## 决定

采用选项 2，复用现有 SQLite、导入管线、设计 token 和图标，没有新增依赖。

- Windows 使用异步 `ReadDirectoryChangesW`，过滤辅助目录通知。启动、窗口重新获得焦点、周期及手动核对兜底；通知溢出触发事实扫描，失败降为周期核对。结束会话先取消并等待未完成 IO，再释放缓冲区和句柄。
- 扫描保留普通隐藏文件和空目录，显式忽略系统辅助项；嵌套库、重解析点、不可读路径分别报告。两次观察相隔 750ms，仍变化的文件留待重试；这不能证明第三方已永久停止写入，执行前仍复核观察和完整哈希。
- 观察记录使用大小、纳秒修改时间和可获得的 Windows 文件身份。文件身份优先，其次现有路径；只有旧对象和新文件双方候选唯一才用完整 SHA-256 关联。文件身份受文件系统约束，含创建时间仍不能当作跨卷永久身份。
- 匹配策略位于 `packages/core/file-reconcile.ts`；应用负责协调与 UX。Rust 只执行受会话、路径、当前版本和观察约束的文件/SQLite 写入，不自行选择合并候选。
- 外部缺失保留对象、标签、描述、来源及评分，显示缺失或不可读状态，不转回收站。歧义由用户关联或保留独立项。原址被另一身份占用时，旧对象释放活动路径，但观察记录保留原路径。
- 更新内容沿用原对象，重建派生信息；数据库提交时保留最新人工字段及标签。编辑人工信息采用字段 PATCH。已回收对象拒绝晚到的导入写入，来源映射按对象身份更新。
- 应用回收原件到 `.ceas/trash/<任务 id>/<原相对路径>`，提交软删除并释放活动路径，不级联删除人工信息。素材预览按回收记录读取原件；没有永久删除或自动清理。
- 每个文件的回收、恢复和移动采用“准备日志 → 不覆盖移动 → 移动日志 → 校验 → SQLite 提交 → 完成日志/归档”。日志使用相对路径，恢复在获得库写会话后进行；中断窗口可幂等重放。
- 源与目标同时存在、源内容改变、版本不符等保留原件与日志，显示重试原因。尚未移动且前置状态仍满足时可取消；准备阶段的恢复/移动可另选相对目标继续。待处理任务阻止根目录改名或迁移。
- 恢复先预览原位置/目标及冲突。批量目标预留不同名字，确认时再次检查；同名保留双方，可指定新收藏集。预览和取消不移动文件。文件操作与导入/核对共同参与切库屏障。

## 代价与边界

观察、哈希和校验增加读盘开销，扫描仍一次返回目录清单；一万对象的纯 TS 计划基准不代表一万原件全流程性能。两次稳定观察只是降低处理中读取的概率，通知也不是事实来源。重试可能需要用户解除占用或选新目标。

当前为文件级任务。稳定目录身份、整目录回收/祖先墓碑、稳定标签关系、备份/修复工具、任务历史与空间管理、原生媒体管线仍未完整交付。未实测移动介质、跨物理卷、网络共享盘和真实断电，不承诺上述环境的数据安全已验收。Linux、网页和离线包仍在后续阶段。
