# ADR 0002：原件使用普通收藏集文件夹

## 背景

用户于 2026-10-28 明确：收藏集就是同名电脑文件夹，文件保留正常名称，可始终用第三方软件管理；目标是桌面推送 Linux、网页只读以及手机离线浏览。此前 00 §2 的内容寻址 Asset 地址、全库唯一哈希及固定收藏集示例不能兑现此要求。

## 选项

1. 保持哈希原件，只提供临时导出普通目录。日常文件管理仍依赖应用，不满足要求。
2. 每项一个包装目录，内部保存原图和 JSON。明确违反用户的文件夹要求。
3. 原件直接置于普通收藏集目录，数据库保存稳定 id、相对路径、哈希与元信息；保留旧哈希原件兼容读取并显式转换。

## 决定

采用选项 3。用户本轮要求优先于旧方案的 Asset 寻址及三层菜单限制。新文件写普通路径；同哈希不同目录是不同位置，允许多个 Item；同地址不同内容保护双方。目录导航 id 是从路径派生的地址，不当作跨端同步主键；后续同步补稳定目录与标签 id。

SQLite 主元数据、单调软删除及旧数据备份保持 ADR 0001 的原则。新增目录读写检查库边界和非 C 盘约束。标签/描述/评分/颜色索引属于辅助数据，可以导出可读 JSON；原件不依赖数据库才能打开。

同步首版限定为桌面写入、Linux 接收、网页与手机只读；不先做多设备同时编辑。发布版本由服务器定序，断网包有明确完整性状态，详见 07。

## 代价

外部软件重命名、移动和内容变更必须与索引协调；当前提供手动重扫和唯一哈希候选关联，实时监听及复杂冲突需继续开发。文件操作与 SQLite 不是一个原子事务：先安全落盘再提交索引，失败时保留原文件，可由重扫恢复；绝不因失败回滚批量删除用户原件。搬移完成后的旧地址清理失败会明确报告，保留两份文件。

旧哈希备份不会自动删除，会多占空间。当前 JSON 导出需要手动刷新，不能直接作为活动同步日志。完整媒体解码与现有 File/URL 字节 IPC 的替换仍为后续任务；本轮 Pixcall 原件复制、归档与扫描的新原生接口只传路径/id/状态。
